# Target architecture and the ordered move list

Phase 3 output of `optimize-volt-cli-architecture`: three independently-biased architects (minimal-move /
seam-first / delete-first), three judges on a fixed rubric, one synthesis. Written by the main loop from
schema-forced JSON.

**Base:** Base is **minimal-move** — all three judges scored it 43 and independently named it base, so there was no verdict to resolve there. It wins because it is the only candidate that opened `DriverBase.cs` before accepting the brief's central causal claim, and the file disproves it: `DriverBase` already carries `using Volt.Engine.Wire;` and `OverlayLiveHealth` already returns `List<ProjectEntry>`, so `BuildHealthResponse` is abstract because two people wrote two caches, not because of the cycle. Its whole downstream cluster closes for one signature change. It is also the only candidate that keeps its hands entirely off `PushService`, `GraphicalCode.Write` and the CODESYS `AssemblyResolve` hook — the three places a mistake reaches a live PLC.

Grafted from **delete-first**: `wire-row-down-to-transport` (unanimous — it REPLACES minimal-move's `pin-the-wire-contract`, and I split it into a relocation move + a mirror-deletion move so each stands alone); `delete-dead-spawn-plan`; and its MONOTONICITY gate argument replacing minimal-move's impossible `RotInstances` red-first test (no test .csproj references `Volt.Cli.Ide.Twincat`, and it is net8.0-windows, so a net8.0 test project structurally cannot).

Grafted from **seam-first**: `pou-refinement-uses-the-core-parser`; the CONST-TABLE half of `partial-xae-probe-fails-loud` (decomposed into a shape move + a fix move — judge 2 disqualified the bundled version for violating the one-kind-per-move rule); the `GuardEmptyItems` half of `cli-identity-from-the-echo` (folded into the init fix — same finding, same file, same principle); the stale `..\..\..\volt-cli\src\` ProjectReference repair; and its guard-scope caveat (`VendorParityGuardTests` enumerates `src/Volt.Engine` only — I verified it, and verified the only vendor literals in Transport live in `Vendors.cs` at the project ROOT, so scanning a new `Transport/Wire/` subdirectory needs no allowlist).

Synthesized, because all three candidates missed it and judges 1 and 3 independently flagged it as certain and nearly free: `bridge-drops-go-to-voltlog` (the `Console.Error.WriteLine("[bridge] …")` second log channel, in a GUI process with no console, carrying exactly the item-DROPPED events the log invariant covers).

**Judge disagreement resolved — the fake/health ordering.** Judge 1 insisted `fake-ide-derives-driverbase` must land BEFORE the health moves; judge 3 refuted this as inherent (the fake cannot supply `SnapshotHealth` before it exists) and noted seam-first contradicts itself on exactly this point. Both are right about something, and I refused to pick a side: `BuildHealthResponse` is abstract TODAY, so the fake can derive from `DriverBase` NOW while still supplying its own `BuildHealthResponse` override. So the fake lands at order 12 (before the health rewrite, putting the probe/degraded/liveness machinery under test for the first time), and `health-compose-in-core` at 13 carries the fake's compiler-forced switch to `SnapshotHealth`. Judge 1's risk ordering is honoured without inventing a dependency that cannot exist.


## The target shape

**Seven projects, unchanged. No new project, no merge, no split, no DI container, no new abstraction. Six source files deleted, four small types moved DOWN, one signature de-abstracted, one signature narrowed, and thirteen named behaviour fixes.**

**1. `Volt.Cli.Transport` becomes honestly THE WIRE.** It already holds the mechanism (PipeServer/Client/Messages/Discovery/Names) and the vocabulary every process shares (`Ops`, `BridgeErrorCodes`, `HealthStatus`, `Vendors`). Four more things move in: `ProjectEntry`, `HealthResponse`, `BridgeDiagnostic` (the ambient-poll row and its diagnostic sibling, ~90 LOC whose only dependency is `HealthStatus`, already there) and `VoltLog` (116 LOC importing only `System`/`System.IO`). The rule that keeps it from becoming a dumping ground: *Transport holds what a process needs in order to speak to a bridge without knowing what a bridge is — the bytes, the words, the health row, and the log file they all append to.* Nothing that reads a project, hashes an item or touches an IDE goes there. `ItemKind` explicitly does NOT move (it would drag `scripts/check-wiring.ts` and four runtimes into a gate the per-move contract does not name). The project is NOT renamed — the seam matters, the name costs a comment, a rename costs the .sln, six csprojs, `build-cli.ps1`, the installer and two source-scanning guards.

**2. `Volt.Engine`'s five-node cycle is cut with ONE edge, and the doc is corrected to match.** Today: `Ide → Wire → Sync → Workspace → Graphical → Ide`. The only edge closing the loop is `Ide → Wire`, and it exists for exactly four symbols: `BuildHealthResponse()` returns `HealthResponse`, `GetBuildDiagnostics()` returns `BridgeDiagnostic`, `SelectProject(ConnectRequest)` takes one, `ExtractLibrarySignatures()` returns `Library.LibSignature` (already acyclic). Move the first two types down and narrow `SelectProject(ConnectRequest)` to `SelectProject(string?)` — verified mechanical: `CodesysDriver.cs:86` ignores `sel` entirely, `BeckhoffDriver.cs:146` reads only `sel.Project`, and `ConnectRequest` stays in `Engine.Wire` as the op's deserialization target. Result: `Wire → Sync → Workspace → Graphical → Ide → {Transport, Library}`. One chain, no new interface, no adapter, ~zero net LOC. `Graphical/` keeps its `ICodeStore` parameter — once the cycle is cut that edge costs nothing, and re-plumbing `GraphicalCode.Write` to bytes churns the FBD/LD path into a live PLC to buy a prettier diagram.

**3. `DriverBase` composes the health response once; the vendor supplies only rows.** `BuildHealthResponse` stops being abstract: cache read → throttle → `OverlayLiveHealth`, over one new `protected abstract void SnapshotHealth()` ending in `PublishRows(rows)`. The row cache, its lock and its clock move up. `IIdeSession` keeps `BuildHealthResponse()` so `BridgePipeHost` and the pipe wire see nothing. A vendor can no longer forget `OverlayLiveHealth` — the invariant that stops `health` reporting green over a dead channel — because it no longer returns a `HealthResponse` at all. A `protected virtual long ProbeThrottleMs` preserves each vendor's cadence byte-for-byte through the shape move, and the fix move that unifies it deletes the knob.

**4. The connector keeps its non-reference to `Volt.Engine`, and that boundary becomes free.** The csproj comment is right — it must survive however different vendor internals get. Its whole price was a hand-written mirror of the health row pinned by two test files in a project referencing `Volt.Engine` for no other reason. Once the row lives in Transport, which `Connector.Core` already references, the mirror, both test files, and that ProjectReference all delete. The boundary was right; only its price was wrong. Same story for `Log.cs`: a 49-line hand copy of `VoltLog` that exists solely because the connector may not reference Engine, and which has already dropped the level gate and the 14-day prune.

**5. The connector's Core/shell line moves to where WinForms actually is.** `BridgeSupervisor` (161 LOC, verified zero WinForms usings — `System.Diagnostics/IO/Runtime.InteropServices` only) and the probe→reconcile→spawn/reap composition move into `Connector.Core`, so the worker de-dup, the crash-restart path and the KILL_ON_JOB_CLOSE orphan guard become reachable from a test assembly for the first time. `TrayContext` keeps the icon, the menu, the windows and the one 4s clock.

**6. Everything below `IIdeDriver` is unchanged.** Both hosting models, in-memory vs file-based PlcOpen, `TcPouReader`, Beckhoff's per-node `try/catch`, both host lifecycles (including `IIdeSession.Disconnect()`, whose asymmetric reachability IS the InIdeLoad/ExternalAttach difference), the `.Tree`/`.Code` partials, the reflection and COM gateways. The one Engine-facing change a driver sees is `BuildHealthResponse` → `SnapshotHealth`, plus a narrowed `SelectProject`.


## Where nothing moves

This section is what proves the phase did not invent work.

**The project count and shape. Seven projects, unchanged: no new project, no merge, no split.** Every candidate for one fails its own test and I name them explicitly so nobody re-derives them. (a) No `Volt.Engine.Transform` for `Graphical/`+`Workspace/`: the engine runs IN-PROCESS inside CODESYS, so the ~1,500 LOC of pure XML/regex transform genuinely needs netstandard2.0 as much as anything else does — the boundary is real but it is a NAMESPACE boundary, and an acyclic using-graph expresses it for free. Cost of leaving it: a `Polyfills.cs` shim and `TickCount64` unavailable in `DriverBase`. (b) No `Volt.Wire` project for the relocated DTOs: a new csproj costs a build target, an installer payload entry and another netstandard2.0 package graph staged into net48, to buy one thing the sink already gives. (c) No merge of Engine into Transport: it would drag ~10k LOC of vendor-facing engine into the always-on tray. (d) No RENAME of `Volt.Cli.Transport`: the seam matters, the name costs a comment, a rename costs the .sln, six csprojs, `build-cli.ps1`, the installer and two source-scanning guards.

**`Volt.Cli.Connector.Core`'s deliberate non-reference to `Volt.Engine` — PRESERVED, and that is the point of move 10.** The csproj comment is right: the connector must survive however different vendor internals get, and `ConnectorSetup.ResolveWorker` means an older connector routinely meets a newer worker. What it needed was never Engine's, it was the wire's. After the row lands in Transport — which Connector.Core already references — the boundary is intact and free.

**`ItemKind` stays in `Volt.Engine`.** Seam-first's `itemkind-down` is refused: it drags `scripts/check-wiring.ts`'s two path regexes, the volt-lsp-iec bundle, the VS Code manifest and volt-control into a move whose per-move gate is build + three C# suites. No judge grafted it.

**`Ops`, `BridgeErrorCodes`, `HealthStatus` and `Vendors` stay in `Volt.Cli.Transport`.** The layering lens is right that the lowest layer encodes decisions it cannot make; it is wrong that moving the file fixes anything, because `Volt.Cli` references BOTH projects. Every client must be able to branch on the codes, including the one that may not reference Engine. `WireVocabularyGuardTests` stays a text scan with a per-file allowlist — narrowed by one entry (PouToXml.cs), never widened.

**`ICodedError` and `PipeDispatch` stay, unchanged.** Both are dependency INVERSIONS with one implementation each; they buy acyclicity, not polymorphism, and deleting either forces `Transport → Engine` and re-creates a cycle. Seam-first's `bridge-exception-down` (which deletes `ICodedError`) is explicitly refused, because keeping it is what makes `one-refusal-carrier` a five-line change instead of a new abstraction.

**`IBridgeWire` and `IProjectSource` stay.** `IBridgeWire` is a truthful test seam — the contract IS the pipe's own shape, so the fake cannot lie. `IProjectSource`'s stated rationale is STALE (the vendor asymmetry now lives above it, and its doc block is syntactically attached to the wrong type), but `FakeProjectSource` lets the whole session/reconcile model run with no pipes, and the alternative — driving `ConnectionManager` through `PerPipeProjectSource` over scripted JSON — makes those tests deeper and worse. A stale doc comment is a doc fix, not an architecture move.

**The three-facet `IIdeDriver` split stays.** The map is WRONG that no production type narrows: `GraphicalCode.Read/Write/DeclarationFrom` take `ICodeStore`, so that facet earns its split twice over (a narrowing production consumer plus a truthful fake). Merging the other two saves two `interface` lines and loses the grouping.

**All of `Graphical/`, untouched.** `PlcOpenReader`/`Writer` and `VgParser`/`VgWriter` are a legitimate two-ended pair whose near-symmetry is the design, not duplication. `GraphModel`, `VgBody`, `GraphConstants`, the five `NetworkStride` declarations — all stay. Critically, **`GraphicalCode.Write` keeps its `ICodeStore`/`ItemRef` signature**: seam-first's `graphical-becomes-pure` re-plumbs the read/splice/import ordering that reaches a live PLC to buy an acyclic diagram, and once move 10 cuts the cycle that edge costs nothing. Judge 3 refused it outright and I agree.

**All of `PushService` and the push path, untouched.** The op algebra, the comparer split, the VG marker predicates, `FlushPendingWrites`, `FakeIde`'s write-recording. `fix-push-data-loss` owns that file; two changes rewriting one conflict-detection loop in parallel is how a live-PLC write path gets broken.

**Both IDE hosts' internal shape, entirely.** `Driver/` facades over an `Ide/` gateway plus a dispatcher; `CodesysObjectModel`/`CodesysTypeMap`/`Reflection.cs`; `TcObjectModel`/`TcPlcOpen`/`TcPouReader`/`RotInstances`/`StaDispatcher`/`ComMessageFilter`. Every load-bearing asymmetry survives: the two hosting models (net48 in-proc reflection vs net8 out-of-proc COM attach), in-memory vs file-based PlcOpen transport, `TcPouReader` having no CODESYS counterpart, **Beckhoff's per-node `try/catch` in the tree walk**, and the host LIFECYCLE difference — including `IIdeSession.Disconnect()`, whose asymmetric reachability IS that lifecycle difference and which delete-first was disqualified for deleting.

**`netstandard2.0` on Engine + Transport, and everything it forces.** `Polyfills.cs`, the System.Text.Json 8.0.5 PackageReference, System.ValueTuple, the nine staged BCL shims, the unchecked `TickCount` subtraction, and the `AssemblyResolve` handler's bare-simple-name matching rule. Hard constraint, correctly so; the only part not required by it (the unscoped match) is deferred rather than guessed at.

**All of `Volt.Cli/Sync/` except the four files three fix moves touch.** `Git`, `Sidecar`, `IdeTree`, `StatusModel`, `Materialize`, `Extensions`, `Scaffold`, `Reporter`, `PhaseProgress` are the CLI's own engine over a workspace the bridge knows nothing about; the placement lens verified this explicitly and it splits cleanly. The apparent double answer to 'is this item pushable' (`Extensions.IsReadOnly` vs the bridge's live CFC/SFC refusal) is a DELIBERATE placement stated at `Extensions.cs:12-14` — not a defect.

**`ControlServer` stays in `Connector.Core`** — the control socket is the connector's published API and belongs with its model. **`Updater`, `Pruner`, `VoltEnv`, `LoginItem`, `CodesysActivation`, `StatusWindow`, `LogWindow` stay in the shell** — no finding pays for moving them and no proposed test would use the seam.

**`Reconciler`'s level-bind / edge-unbind asymmetry, `Session`, `ConnectionManager`'s startup grace hold and lease expiry, the per-pid pipe topology, and `PipeDiscovery`'s P/Invoke.** All correct, all untouched. `Reconciler`'s asymmetry in particular is the fix for a real field bug (opening a workspace in VS Code gating the CODESYS bridge a terminal `volt push` was using) and must not be "simplified".

**The item-NAME identity invariant.** No duplicate-name guard is added anywhere, in any move. Same-name items keep collapsing last-write-wins.

**`structureVersion`'s hash basis, and the `Ops` string-keyed dispatch table.** Unchanged; the former gets a doc correction only.

## Open questions for the user

- **What is the unified health-probe interval?** `unify-probe-throttle` (order 14) collapses two cadences into one Core-owned number. 5000ms matches TwinCAT and is ~1 probe per 4s tray poll, but CODESYS's `SnapshotHealth` (a reflection object-model read, in-proc) is MUCH cheaper than TwinCAT's cross-process STA round-trip, so the honest shared number may be smaller. The user-visible consequence of the larger number: a CODESYS project OPENED in the IDE with no explicit select takes up to the interval to appear in the tray (a rebind still shows at once, because `SelectProject` calls `SnapshotHealth` directly). So the entire mechanism is verified by the live e2e and by an engineer noticing.

The specific ways it goes wrong: (a) moving the row cache into the base gets the publication discipline wrong, and TwinCAT's `_cachedProjects` — the one piece of state deliberately readable off the COM apartment — starts being read torn on the poll thread; (b) throttling CODESYS to 5s delays a newly-opened project's appearance in the connector's list, and although `SelectProject`/`Connect` call `SnapshotHealth` directly so a BINDING still shows at once, that is exactly the kind of claim that is true in the code and false on a live IDE; (c) making the TwinCAT probe throw on `ProbeIdeAlive() == false` turns every transient COM hiccup into a degraded row and a flickering tray, because `MarkDegraded` is not sticky but the poll is fast.

The mitigation is the ordering, and it is not optional: `fake-ide-derives-driverbase` must land BEFORE any of the three, so that for the first time a test can drive a real `DriverBase` through a degraded channel, a stale clock and a cached row that names a different project than the live one. Every one of these three moves must arrive with a red-first or green-preserving test running through that fake, and the close-out live e2e (CODESYS 92/0, TwinCAT 88/2) is the only thing that can confirm the CODESYS throttle change. If the fake cannot be made to derive from `DriverBase` while keeping the ~500 unit tests green, that redness is itself the finding — and the health moves stop until it is understood, because it would mean the divergence the fake hides is larger than the audit found.


### Candidate: delete-first — 16 moves

**Does not fix.** **`BridgeErrorCodes` stays in `Volt.Cli.Transport`.** The layering lens proposes moving it up beside `BridgeException` so 'a pre-wire client refusal cannot be spelled as a wire code'. It would not achieve that: `Volt.Cli` references `Volt.Engine`, so `BridgeResolver` could still spell `PLC_DISCONNECTED` from wherever the table lives. The move deletes nothing and prevents nothing — it is a re-placement that closes a finding on paper. The real defect (five origins, four different remedies, behind one code an agent branches on) is a wire-contract change, and the brief fixes error codes per failure.

**The CLI's two refusal carriers (`BridgeError` vs `PipeCallException`) stay two types.** The proposed fix is a shared coded interface — a new abstraction on a path where the concrete cost is that one command's `--json` output degrades to a stderr line. Adding an interface to unify two exception types in one project is precisely the move this candidate exists to refuse; the honest fix is to resolve the bridge inside each command's `try`, which is a CLI command-layer change with its own tests.

**`refs` still carries no identity on the wire.** Giving it `expectedPlatform`/`expectedProjectName` plus an echo is a protocol ADDITION on four DTOs that changes what `volt status` refuses. It is a genuine `certain` finding, and it belongs with the change that owns the precondition split (`audit-volt-cli-src`), because it is the same invariant.

**The CODESYS `AssemblyResolve` handler keeps matching by bare simple name.** The proposed one-line guard — return null unless `e.RequestingAssembly` is one of Volt's three — is cheap and the charter argument for it is strong (Volt handing its `System.Memory` to a third-party CODESYS plugin at the CLR loader). I am not taking it because `RequestingAssembly` is frequently NULL in exactly the `Assembly.LoadFile` context this handler exists for, so the guard can break the bind it was written for, in a process driving a live PLC, with no offline test and a symptom (health fails to serialize, the connector cannot attach) that looks like something else entirely. It needs a live CODESYS experiment, not a code review.

**`structureVersion`, the five `NetworkStride` declarations, `GraphConstants`, `PushService`'s mixed case comparers, and the bare-vs-full name typing** are all left standing. Each is real; none has a cost that survives the question 'what breaks for a user this month'. `structureVersion` has no production reader at all, which is an argument for deleting the field — but it is on the wire, and deleting a wire field is a protocol change I will not smuggle into a shape batch.

**`BridgeSupervisor` stays in the WinForms assembly and the orphan-worker job guard stays untested.** The placement lens is right that it is pure `Process`/job-object code on the wrong side of a framework line, and moving it would buy a test seam for ~160 LOC. I am refusing because the move drags the tray's tick composition (`_supervisor`, `_twincatExe`, `TwincatWorkerId`, the `RestartWorker` string round-trip) into Core to be useful, which is relocation-as-architecture — and `bun run test:install` already exercises worker lifetime, spawn and orphan cleanup on a real machine, N times. What I take instead is the deletion: the spawn plan production discards, and the test that asserts it.

**The e2e harness's frozen `PIPE` const and the ControlHarness's opposite reconcile** are both left. They are test-infrastructure defects in a TypeScript suite, and this change's gate is the three C# suites; fixing the harness's pipe resolution changes which bridge the suite drives, and fixing the ControlHarness turns `connector.e2e.test.ts` red pending a product decision about the session model. Both are named, both are documented, neither is mine.

**LOC delta.** **≈ −700 src LOC against the 15,295 baseline (−4.6%), plus ≈ −150 test LOC and −6 src files / −3 test files.** Net-negative is the deliberate outcome, not a side effect: 9 of the 16 moves delete more than they write, and only two add anything at all.

The `$"{kind}\n"` arm, three `CodesysTypeMap` classification arms and three table rows **≈ 12**.

The one thing that grows is `Volt.Cli.Transport` (+ ≈ 210 LOC, from 432 to ≈ 640). That is the deliberate trade: the sink project takes on the four types every process already needed, and in exchange the Engine's dependency cycle, one duplicated DTO, one duplicated logger, and two test files that existed only to hold duplicates together all disappear. A project that grows while the system shrinks is a project that stopped being a place to hide things.

**Biggest risk.** **Four of these moves change code that no offline test can reach, and the live suite that would catch a regression is already partly red.** `Volt.Cli.Ide.Codesys` has ZERO C# test dependents — no `.csproj` in the repo references it, and `CodesysTypeMap`, `CodesysDispatcher` and `CodesysObjectModel` are exercised only by a live IDE. `Volt.Cli.Ide.Twincat` is the same: grep across `test/` finds no reference to `BeckhoffDriver`, `TcObjectModel`, `StaDispatcher`, `RotInstances`, `TcPlcOpen` or `TcPouReader`. So `delete-debug-surface`, `health-composed-in-core`, `probe-must-prove-liveness` and `no-constant-manifests` all pass the three C# suites trivially — the suites cannot see the code they change — and the only real check is the live e2e (CODESYS 92/0, TwinCAT 88/2). The two known TwinCAT failures are a diagnosed harness defect, which means there is already a place for a real regression to hide: a new TwinCAT failure will look, at a glance, like the failure everyone has learned to ignore.

The mitigation is ordering and discipline, not more structure. Land every shape move that CAN be checked offline first (`delete-pou-to-xml`, `one-st-emitter`, `wire-row-down-to-transport`, `voltlog-down-to-transport`, `delete-dead-spawn-plan`, `fake-ide-earns-its-keep`) so the vendor-facing moves land against a suite that has just been strengthened — in particular `fake-ide-earns-its-keep` puts `DriverBase`'s degraded/liveness/probe machinery under test for the first time, which is exactly the machinery `health-composed-in-core` and `probe-must-prove-liveness` rewrite. Run the live e2e at the `health-composed-in-core` boundary and again at close-out, and record the TwinCAT pass count BEFORE starting so 88/2 is a number being compared, not a story being told.

The second-order risk sits in one move: `no-constant-manifests` removes files from users' existing workspaces on their next pull. It is the right call — a file that looks tracked and records nothing is worse than no file — but it is the only move in this set whose blast radius reaches a repository someone else owns, and it is the one I would land last, alone, and behind a release note.
