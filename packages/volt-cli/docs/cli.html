The volt CLI

The third surface, and the one most people meet first. It is a client — everything it does, it does by calling the wire and by running git.

It is git, not a sync tool

volt init makes the project root a real git repository, and the live IDE is modelled as a remote-tracking branch: refs/remotes/volt/ide. So pull fetches the IDE and lets native git merge do the reconciliation, and push writes to the IDE and fast-forwards that ref. There is no custom three-way merge engine and no .volt/ snapshot directory — the history of what the IDE had is git log volt/ide.

Gating the mutating verbs is the HOST's job. init, pull, push and merge write to a live PLC, so an agent should confirm before running them — but that confirmation belongs in the host's own permission system, not in Volt. The CLI annotates; it does not enforce.

Finding the bridge

in orderhow
1--pipe <name>, or VOLT_PIPE — names one exactly. This is what the tray's shells set, and what the e2e tier uses.
2The workspace binding's vendor (.git/volt), which names the pipe PREFIX to discover by.
3--vendor codesys|twincat on the command line, for a workspace that has no binding yet.

A bridge that cannot be reached is not a crash: the CLI prints "bridge is not reachable — is the IDE bridge running?" and exits 1. Timeouts and IO failures land there too, deliberately — from a caller's side they are the same condition.

The verbs

Each one can be run below. Verbs marked writes are refused unless the console was started with --allow-write.

Exit codes

The part --help never tells you, and the part a script actually branches on.

There are only two. The reason for a failure is on stderr, not encoded in the code — so a script can tell success from failure and must read the message for anything finer. volt with no verb prints usage and exits 0; an unknown verb prints the same usage and exits 1.

Machine-readable output

--json on init, pull, push, status and build prints a single JSON object instead of prose — that is the interface for a tool or an agent. status also has --porcelain for the git-shaped short form, and --local to answer without touching the bridge at all.
