Overview

A bridge exposes one running PLC IDE — CODESYS or TwinCAT — over a Windows named pipe, as JSON. Everything above the pipe is a client: the volt CLI, the connector tray, the VS Code extension, the e2e harness. The pipe is the boundary, and it is the thing to build against.

Both vendors serve byte-identical responses for the same project. That is deliberate and gated — a client never learns which vendor it is talking to except by asking, and vendor differences live below the seam as data, never as branches in a caller.

This page is generated. The op list, every schema and every field come from volt-bridge.openrpc.json, which is itself produced from the C# contract types by BridgeSpecTests and re-checked on every build. If the wire changes and the document does not, the build fails. Open the spec →

The two layers

There are two surfaces here, and which one you want depends on what you are building. A client that wants a project as text uses the wire. A project that wants to drive an IDE itself implements or consumes the driver interface — the layer below the pipe.

Everything shareable lives in Volt.Engine above the seam; only irreducible vendor glue lives in a driver. That is what keeps the two vendors answering identically — the services are the same code.

Transport & framing

One named pipe per live IDE, named volt.bridge.<vendor>.<pid> where the suffix is the IDE's process id. Clients discover by prefix, because the pid changes whenever the IDE restarts — never hard-code a full pipe name.

request
{ "op": "fetch",
  "body": { "knownItems": {}, "onlyItems": ["FB_Motor.fb"] } }
response
{ "projectVersion": "…", "changed": [ … ], "items": { … } }

// or
{ "error": { "code": "PLC_DISCONNECTED", "message": "…" } }
Long ops stream progress. refs, fetch, init, push and build emit ProgressFrames before the final result, so a client can show a bar instead of a spinner. health never does — it answers from a cached snapshot and is the one op that is safe to poll while a push or build is running.

Error codes

Every failure is a coded error, not a message a client has to pattern-match.

codemeans
PLC_DISCONNECTEDNo project is bound, or the bridge is paused by disconnect. Send connect.
WRONG_PROJECTThe bound project is not the one the request named (expectedProjectName).
BAD_REQUESTUnknown op, or a body the host cannot read.
NOT_FOUNDThe named item does not exist in the project.
UNSUPPORTEDA shape this vendor's driver cannot write — the message says what and what to do instead.
DUPLICATE_CHILDA create collided with something already there.
INVALID_CODE_HEADERThe pushed source's header is not one Volt recognises.
INVALID_STThe pushed body failed the ST or network-text gate.
NO_SIDECARThe workspace has no bound-project record.
INTERNAL_ERRORAnything else. A bug — the log has the detail.

The driver layer — IIdeDriver

This is the layer to reuse if you want to drive a PLC IDE from your own project. It is one interface, composed of three, and a driver is the only place that knows a vendor.

The one rule that matters: ICodeStore speaks ItemContent and nothing above the seam knows a vendor's own representation. A graphical body crosses as network text; the driver converts. Get that boundary right and the rest of the engine is vendor-blind for free.

IIdeSession — is there an IDE, and which project

membernotes
IsConnectedIs a project bound and servable right now.
Vendorcodesys or twincat. The only vendor fact above the seam.
ServedProjectNameWhat is actually bound — checked after connect so both vendors refuse identically.
IdeVersionThe IDE's own version string.
SelectProject(ConnectRequest)Bind (or rebind) a project. Empty name = "serve whatever you have".
RunOnStaThread<T>Load-bearing. Both IDE automation surfaces are STA; every IDE-touching op is marshalled through here.
IsDegraded / MarkDegraded / ClearDegraded / ShouldMarkDegraded / RecoverThe health state machine — an IDE that went busy or dropped a call is degraded, not dead.
BuildHealthResponse()The cached snapshot health answers from. Never marshalled.
FlushPendingWrites()Settle anything buffered before a read or a receipt.
Build() / GetBuildDiagnostics()Compile, then read the IDE's own diagnostics.
ExtractLibrarySignatures()Referenced-library signatures, for analysis clients.

IProjectTree — structure

membernotes
WalkItems()Every tracked item, once, with its folder path. The basis of refs/fetch.
GetTreeRoot()The node folder paths are relative to.
ChildCount / ChildAt1-based child access. May fault on a subtree the vendor cannot read — callers treat that as a leaf, not a crash.
Parent / Name / KindCodeNode identity. KindCode maps through ItemKind.
HandlesSurviveStructureChangeWhether a create invalidates existing handles. False on TwinCAT — callers re-resolve.
CreateChild / Delete / Rename / MoveStructure writes. A folder is not an entity: it is created on demand from an item's path, and a push prunes the ones it empties (the way git removes a directory once its last file goes).

ICodeStore — content

membernotes
ReadContent(ItemRef)Declaration, body and members as ItemContent. Graphical bodies come back as network text; a body with no text form comes back as a marker.
WriteContent(...)The write, including members. pushedDeclarations lets an item resolve a type another item in the same push declares.
ReadManifest(ItemRef, kind)Non-source descriptors (libraries, devices, tasks) as text.
WriteTask(ItemRef, TaskSettings)A task's schedule — the one descriptor that is writable.
ValidateSource(...)The push pre-flight. Every refusal decidable from source text, raised before the first write, so a push that cannot land in full lands nothing.
