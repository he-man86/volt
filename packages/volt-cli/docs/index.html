Volt, end to end

Volt turns a live PLC project into text you can keep in git, and puts edited text back. Four pieces do that, in a chain. These pages follow the chain — and every endpoint on them can be called.

Steps 3 and 4 are separated by the vendor seam: everything above it is identical for both IDEs, so a client never learns which one it is talking to except by asking. What travels along the chain is documented apart from it — items and kinds (what a project is made of) and network text (how a graphical body becomes editable text).

Try it, rather than take the page's word

Three of the four are reachable from outside, and none of them can be exercised by a page on its own: a browser cannot open a named pipe, the connector refuses cross-origin requests by design, and argv is not something a page has. So the volt binary serves these files itself and stands behind them. 

volt console                  # read-only — calls run for real, nothing can change a project
volt console --allow-write    # also enables push, the mutating verbs and control-plane writes

Every op, route and verb then carries a Send panel: an editable request, and the raw answer — progress frames included, exit codes included. Opened as plain files instead, the pages render the same and say plainly that nothing can be called.

One pull and one push, all the way down

The chain in a concrete run, so the four pages have something to hang on.

sequenceDiagram participant U as you participant C as volt CLI participant K as connector participant B as bridge participant I as IDE U->>C: volt pull C->>K: which bridge serves this project? K-->>C: the pipe for it C->>B: refs B-->>C: every item's version C->>B: fetch { knownItems } B->>I: walk + read what changed B-->>C: progress… then the items as text C->>C: git merge into your branch Note over U: edit the text, commit U->>C: volt push C->>B: push { expectedProjectVersion, ops } B->>B: PRE-FLIGHT — every text-decidable refusal B->>I: apply what survived B-->>C: accepted, or conflicts with nothing written

Two rules from that run are worth carrying into every page. A push that cannot land in full lands nothing — everything refusable from the source text alone is decided before the IDE is touched. And the IDE is a git remote: pull fetches it into refs/remotes/volt/ide and lets native git merge reconcile it, so there is no bespoke merge engine to learn.
