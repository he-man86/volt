Network text

The FBD/LD source form: a literal transcript of the vendor's network model (NWL). One statement per NWL item, nesting where the vendor nests, and a name only where the vendor names something. This is network text v2, written by every pull since MATERIALIZATION 3 (openspec/changes/network-text-literal-nwl); text in the previous form (v1: LET, numbered NETWORK <n> <LANG> headers) is refused with a message to re-pull (migration). Where a spelling rests on a census, the census is named (tasks.md §1).

What v2 changed and why

Each intermediate name in v1's text carried one NWL fact through the round trip — a fan-out point, a leaf that is not a token, several coils on one item, the enable wire. v2 keeps every fact and moves it to where NWL keeps it: the pin, the operand, the statement's shape, the header.

Decisions from the 2026-09-26 review

  1. Edges are R_EDGE(x) / F_EDGE(x), IEC's own edge words, call-shaped like every other non-infix construct. They spell a flag on the operand (Rtrig/Ftrig in IFlags), not a box: R_TRIG would be an FB box with an instance the IDE never held, and a real R_TRIG box the engineer drew must stay distinguishable from it. With negation the one order is R_EDGE(NOT x): the vendor negates before it detects the edge (census 1.14, DIALECT N17), so NOT R_EDGE(x) would say other logic and is refused. One corpus use (pro2193 ActuatorFB, an edge on MOVE's EN), so it keeps a spelling.
  2. No whitespace rule for NOT. Tokens separate the modifier from the box, and parentheses are structural: every pair is a box — a group's, or a call's argument list. NOT a and NOT (a AND b) are the modifier; NOT(a) and NOT((a AND b)) are the NOT box. A redundant pair (((a AND b))) is refused, never read as grouping.
  3. Every statement ends with ;, the IF form and EXECUTE included (END_IF;, the ST keystroke). The empty item is the empty statement — a ; that closes nothing, on its own line — the same "nothing" every empty slot already is (coil := ;, f(a, )). Rejected: EMPTY;, which reserves a word a variable may carry and collides with a top-level leaf.
  4. Keep S=/R= and chained assignment — native ExST with the same level semantics: the target is set (reset) on every scan the value is TRUE, not on its transition.
  5. Pull never throws. Anything the writer cannot spell sends the body to the existing marker; push refuses by name. The vendor facts it has no spelling for — pin flags, item flags, nested Demux — are measured (census 1.13, 1.1, 1.8) and routed there by name (marker on pull, measured).
  6. Wires are declared in a per-network VAR_TEMP … END_VAR below the header and comments, not in a header field — ordinary ST declarations the LSP hovers like any other. Type: read off the producer, one rule for FBD and LD and for writer and reader: the vendor's stored output type where it has one, else BOOL for a boolean producer; a wire whose type nothing says goes to the marker, never guessed. Rejected: a pseudo-type WIRE (lossless, but not compilable ST) and a writer-inferred data type (needs POU and library declarations the writer lacks, and NWL has no field to keep it).

Edge cases that disappear

  • Hoisting and minting: an enabled box at operand position vanishing unless hoisted; render order having to equal text order or the gate refused Volt's own output (fc_CamC_CC_Base, TrayFiller); XOR-combining modifiers on substitution. Nothing is hoisted, minted or substituted.
  • EN echoes: three fold paths, echo-before-use-count, LET en1 := ; (9 POUs), IF en THEN LET m := …. Now an EN pin and .ENO.
  • Classification: g vs m spelling near-identical lines (573 Demux vs 40 multi-coil assigns); prefix for minted names, use count for hand-written ones. Only the VAR_TEMP declaration decides now.
  • Leaves and whitespace: an unsafe leaf at statement position reading back as a box; i-text never to be parsed (23 Lenze networks); the a .b spacing rule; NOT( vs NOT (. The backtick and structural parentheses cover all four.
  • Silent reshapes: a result pin reading back as an Assign; a Parallel coming back as AND/OR; TwinCAT's Unhoist fallback.

Why the LETs got complex

Each family was the only place the text could hold one NWL fact. None needs a statement of its own.

familyNWL information it carriedwhat carries it now
g<VarId>A Demux exists (even with one consumer — 3 Lenze networks, C10d/D30), its VarId, its position as a top-level item, and every nested reference.Still a name — the one node NWL names. Declared in the network's own VAR_TEMP block, defined by native assignment. Why not lighter: no name duplicates the producer into extra boxes; a reserved pattern alone lets a coil on a real variable G3 silently become a Demux; VarIds are per network, so a body-wide block collides. The Demux holds no type, so the type is read off the producer (below).
m<n>One Assign with N OutputItems, each with its own storage — distinct from a Demux feeding N assigns.The chained assignment: one statement, one item.
i<n>One operand whose typed text must never be parsed into boxes.Backticks at the operand's own position. A backtick cannot occur in ST, so it cannot collide; parentheses could ((iRPM * 6) is also a box).
en<n> + IFThe enable tree in slot 0; EN shown even when unwired; the rung continuing out of ENO.EN := pin and .ENO.

The writer's only state is the VarId→name map; the reader's is the wire set its VAR_TEMP declares. No prelude, fold, substitution or counter. The writer never throws: a shape it cannot spell sends the body to the marker.

Grammar

body       = marker , NL , { network } ;
marker     = "(* @volt-implementation" , ( "FBD" | "LD" ) , "*)" ;
network    = header , NL , { comment } , [ wires ] , { statement } , "END_NETWORK" ;
header     = "NETWORK" , [ "LABEL:" , name ] , [ "TITLE:" , title ] , [ "DISABLED" ] ;   (* ends at its newline *)
wires      = "VAR_TEMP" , decl , { decl } , "END_VAR" ;                 (* one per network, if it has a Demux *)
decl       = wire , { "," , wire } , ":" , type , ";" ;             (* type read off the producer *)
title      = '"' , { char - '"' - "$" - NL | "$N" | "$R" | '$"' | "$$" } , '"' ;   (* ST's string escapes *)
comment    = "//" , { char - NL } , NL ;                            (* ends at its newline *)
wire       = "g" , digit , { digit } ;

statement  = ( assign | jump | cond | value ) , ";" ;               (* ONE per NWL item *)
cond       = "IF" , value , "THEN" , jump , ";" , "END_IF" ;
assign     = lvalue , op , { lvalue , op } , value ;                 (* a lone wire target = Demux *)
op         = ":=" | "S=" | "R=" ;                                 (* "S =" is "S=" after a target *)
jump       = "JMP" , name | "RETURN" ;                               (* any identifier after JMP is the label *)

value      = [ "NOT" ] , ( edge | core ) | (* empty *) ;
edge       = ( "R_EDGE" | "F_EDGE" ) , "(" , core , ")" ;          (* a flag, not an FB *)
core       = group | call , [ ".ENO" ] | execute , [ ".ENO" ] | parallel | operand ;
group      = "(" , value , operator , value , { operator , value } , ")" ;   (* one operator kind *)
call       = [ "???" , ":" ] , head , "(" , [ pin , { "," , pin } ] , ")" ;  (* "()" = no input slot *)
head       = boxtype | name | backtick ;                             (* NOT(…) is the NOT box *)
pin        = [ name , ":=" ] , value | [ name ] , "=>" , [ lvalue ] ;
execute    = "EXECUTE" , [ "(" , "EN" , ":=" , value , ")" ] , NL , st-lines , "END_EXECUTE" ;
parallel   = "PARALLEL" , "(" , [ "MODE" , ":=" , mode , "," ] , [ "IN" , ":=" , value , "," ] , value , { "," , value } , ")" ;   (* MODE only off its default *)
operand    = token | backtick ;
lvalue     = token | backtick ;
backtick   = "`" , { char - "`" } , "`" ;
operator   = "AND" | "OR" | "XOR" | "+" | "-" | "*" | "/" | "MOD"
           | ">" | "<" | ">=" | "<=" | "=" | "<>" ;
  • Terminators: every statement ends with ; — IF a THEN JMP Done; END_IF; and END_EXECUTE; too. That ; belongs to its statement; only a ; that closes nothing is the empty item, written on its own line.
  • Parentheses are structural: a pair is a group's (it holds an operator) or a call's (it follows a head). After NOT, a pair holding an operator is a group under the modifier; any other pair is the NOT box's argument list. After an operator word (AND, MOD, …) the same: a pair holding an operator at its own depth is a group, so the word was the operator after an empty slot (( AND (x OR y))); any other pair is the word's argument list (AND(EN := go, a, b)). Spacing plays no part. A pair that is neither is refused.
  • Call heads: an operator or function box's head is its BoxType verbatim — bare when it is one name and no word of the text other than the operators' own (ADD, MOVE, AND, GE, MAX, NOT), else between backticks (a POU named Network is called `Network`(x)). An operator type spelled otherwise than the table (and) keeps its spelling in call form, never infix. An FB box's head is its instance. The FB's type is taken from the instance's declaration, and a declaration names a NAME — so an instance whose text is an expression (fbs[1], SUPER^, census 1.12: one in every corpus) is declared by no name and goes to the marker, and a push of `fbs[1]`(IN := a) is refused rather than read as a function named fbs[1]. A function box named like an instance in scope goes to the marker too: its head would read back as that instance.
  • lvalue: an assign target or a => v pin is a token or a backtick, by the same rule as an operand (`arr[i + 1]` := x;, `a .b` := x;). => with no lvalue is an output slot connected to nothing.
  • Reserved: PARALLEL, R_EDGE and F_EDGE as a POU or instance name are refused. A wire name is g<digits> and must not match, case-insensitively, any name in scope — POU variables, globals, the owning FB's members from a method, keywords, literals. Writer and reader use the same set.

Newlines and whitespace

Newlines are significant in exactly three places: the header ends at its newline, each // comment line ends at its newline, and an EXECUTE body runs from the newline after EXECUTE[(…)] to the first line whose first word is END_EXECUTE. A header is only the whole word NETWORK at a line start outside an EXECUTE body (NetworkState := 1; is not one). So a line after NETWORK that starts DISABLED :=, TITLE := or LABEL := is a statement, never a header field. Elsewhere, whitespace and newlines are layout — except inside backticks, TITLE strings, comments and EXECUTE bodies. S= / R= are the word and =, so x S = a; is x S= a; and (R=x) compares a variable R: after a target the pair is the storage operator, inside a group it is a comparison. A CR LF line ending is layout everywhere, in a comment and an EXECUTE body included. The operator table is unchanged (FbdOperators.cs).

Body marker. An ST body keeps the bare (* @volt-implementation *). A graphical body carries (* @volt-implementation FBD *) or … LD *), one per body: an FB with an ST body and an LD method carries a bare marker on the FB and an LD marker on the method; a property's two accessors carry one each. (* @volt-graphical: CFC *) (BodyMarker) is unchanged: it marks an unsupported body and carries no network text.

Header and comment

  //     step 1 — wait for the tray

  // // a line that itself starts with two slashes

  g0 := TRUE;

The header fields have one order (LABEL, TITLE, DISABLED); another order is NETWORK_NOT_CANONICAL. The comment is the network's one Comment: its // lines sit between the header and the wire block (or the first statement), and a // after a statement is NETWORK_PARSE — NWL has no per-item comment, so moving it would be silent. Per line, the // and one following space are syntax; the rest, leading indentation and a leading // included, is text. An empty comment line is //; a blank line between // lines is layout, not part of the comment. The indentation before // is layout. Trailing whitespace is kept on read; the drivers trim the vendor's trailing newline (C8) and compare ignoring trailing whitespace, so an editor that strips it writes nothing.

Wires — the one named thing

NETWORK TITLE: "DONE Network 1: Activating/deactivating MID-S/Trayfiller"
  VAR_TEMP g0, g1 : BOOL; END_VAR
  g0 := TRUE;
  g1 := (g0 AND NOT Mach1_Safety.Status.Custom_ATF_Disabled);
  Mach1_AuxData.TrayfillerActive := g1;
  HMI_Var.TrayfillerActive := g1;
  Mach1_AuxData.MIDS_Active := (g0 AND TRUE);
END_NETWORK

Mach1_MIDS network 0, the left rail. g0 := and g1 := are Demux items with an Input (each a top-level item); the two bare g1 are nested references. Five statements for five items. A consumer that is not a declared wire — what the old page called a sink — is an ordinary coil.

The block. A network with a Demux has exactly one VAR_TEMP … END_VAR, after its // lines and before its first statement; a network without one has none. VAR_TEMP because a wire's value exists only while the network evaluates; per network because VarIds are. Canonically one line; the reader also takes it across lines (VAR_TEMP / g22 : BOOL; / END_VAR), as ST does. Wire-ness comes from the declaration only — never use count, never a prefix — matched case-insensitively. g<digits> carries the VarId, so a wire keeps its name (C9). The writer emits items in vendor order and never reorders; a vendor order that references a wire before defining it goes to the marker.

The type comes from the producer, one rule for FBD and LD, applied by the writer to declare and by the reader to check. The Demux holds no type, so the text may not invent one. The vendor's stored output type of the connected slot comes first (a bitwise AND on WORDs is a WORD). Otherwise BOOL: a comparison, TRUE/FALSE, an edge, .ENO, PARALLEL, an AND/OR/XOR/NOT box (BOOL or the bit-string type the text declares), and a leaf whose EVERY use is boolean — an EN, a PARALLEL, a jump condition, an edge on the reference, and in ladder a coil or contact (task 1.17). A leaf feeding a data pin, and a data box with no stored type, say nothing: the wire goes to the marker on pull, never guessed, and a hand-written declaration is taken as written. The gate checks a declared type against what the producer says and refuses a mismatch by name — the IDE has no field that would keep it.

Infix groups and the NOT box

out := ((a AND b) OR c);
out := NOT a;
out := NOT (a AND b);
out := NOT(a);
out := NOT((a AND b));

A group is one operator box. NOT a is the negation modifier on an operand; NOT (a AND b) the modifier on an AND box's output; NOT(a) the NOT box; NOT((a AND b)) the NOT box around an AND box [RoundTrip L134–135, roundtrip.test.ts L25]. Spacing plays no part: each pair of parentheses is exactly one box.

Infix rests on census 1.5, which measured it. The reader reads InputParams names for every box (CodesysNetworkReader L184). Infix is used when the box has no EN, no instance, no output pin, no consumer connected by its ENO, and its formals are the operator's defaults or absent — the two are one text, and the driver writes the defaults. Only a non-default formal forces call form. Without that rule, default formals such as IN1/IN2 would turn every rung into AND(IN1 := a, IN2 := b).

Edges

MOVE(EN := R_EDGE(bStart), 1, => nMode);
out := F_EDGE(NOT x);
lamp := R_EDGE((a AND b));

A rising edge on MOVE's EN (the pro2193 ActuatorFB shape); a falling edge of a negated operand; an edge on an AND box's output — the outer pair is R_EDGE's, the inner the group's. The argument carries no modifier but one NOT, which is the node's own negation: the vendor negates first, on an operand and on a box alike, so R_EDGE(NOT x) is Negation+Rtrig and NOT R_EDGE(x) is refused (census 1.14, DIALECT N17; measured on CODESYS — TwinCAT's order is not, so its driver sends such a body to the marker). A Parallel or a wire reference holds no flag at all (N20): R_EDGE(g3) is refused, and the edge goes on the wire's producer. And R_EDGE(NOT(a)) is an edge on the NOT box — its pair holds no operator, so it is NOT's argument list, as everywhere; nested edges and rising+falling on one operand are refused by name.

EN, ENO and output slots

MOVE(EN := a, b);
MOVE(EN := c, 0, => Status);
AND(EN := go, a, b, => out);
GT(EN := SUB(EN := rung, light, deviation, => diff).ENO, sensor, diff, => out);

A MOVE with EN wired and its output going nowhere (v1 MOVE(a, b);, 34 networks); a MOVE writing its own result pin; an operator box in call form because it has EN [parity-fixes.test.ts L49]; and the EN-chained FBD pair from SideCorrection [RoundTrip L61] — a SUB's ENO enabling a GT, each writing its own pin.

The slot rule. The model carries each output's slot index and, on a consumed box, the slot its consumer is connected to; the text spells that stored slot:

  • ENO is never an => slot. It is only ever .ENO.
  • A consumed box connected by its ENO output says .ENO, and that wins where ENO is also the main output (every box whose outputs start with ENO), so one model has one text; connected by a main output that is not ENO it has no suffix. Census 1.6 (DIALECT N16) found no other: every export connection that names a slot names MainOutputIndex (338 checked, none disagreeing), and that slot IS the ENO output exactly when the box has one. Any other connection slot goes to the marker. A pushed consumer without a suffix on a box the IDE gives an ENO main output is refused, naming the box — the mirror of .ENO on a box with no ENO.
  • The text does not say WHICH slot the main output is, so it reads it by rule: slot 0, and for an AND/OR/XOR/NOT box (which the vendor stores no main output index for — census 1.6) no stored slot. The rule is the same for a group and a call: (a > b) and GT(a, b) read to one box, connected by slot 0, and the slot never decides infix — except ENO: a group has no suffix position, so an operator box consumed by its ENO is a call, out := ADD(a, b).ENO;, never (a + b), which is the same ADD consumed by its data output. A box the rule would misread goes to the marker: a main output stored as another slot (1 on 3 Lenze call boxes), or a consumed box whose connection slot was never read. Renumbering its pins instead would wire them to other slots on push.
  • Positional => v pins fill the remaining output slots in order, skipping the connected one. A named F => v goes to slot F.
  • .ENO means "connected to the ENO output", never "the box has EN" — the two are independent (census 1.6). An enabled comparison has EN and no ENO, and its consumer reads its one data output: out := GT(EN := c, a, b); (40 boxes in the corpora). An FB may declare ENO without EN (Lenze Dryer), and an Execute box has no output but ENO, so END_EXECUTE.ENO needs no EN (census 1.11). The push refuses .ENO on a box the IDE gives no ENO output.

So coil := MOVE(EN := c, 0, => dst).ENO; is "dst gets 0, coil gets ENO": a MOVE showing EN/ENO has ENO as its main output, and its consumer reads ENO (66 connections, census 1.6). GT(ADD(EN := x, a, b), c) would claim GT reads ADD's data output, which no measured ADD with EN is connected by; the push refuses what the IDE's box cannot connect.

The gate

Body language (the marker matches the IDE's view), then parse, then a token fixed point: Tokens(Write(Read(x))) == Tokens(x) — re-wrapping a long call one pin per line passes, changing a token does not, and no minted name is left to get "wrong". A separate test oracle checks Read(Write(m)) ≅ m over every vendor-read fixture: the check that sees pull-side loss, which a text fixed point cannot. Its one equivalence is absent ≡ default formals.

Layout after a push. The writer has one canonical layout. After a successful push the CLI records the IDE's re-materialized — canonical — text as volt/ide and brings the working tree to it, as a formatter would. A hand layout therefore lasts until its push and never reappears as an IDE-side change on a later pull; an item the push did not touch is not re-fetched. Only a layout is adopted: an IDE that holds a pushed item as other tokens holds another program, so the working tree keeps the pushed text, the push names the item, and the next pull brings the IDE's text in as the IDE-side change it is.

The language server

A VAR_TEMP wire is an ordinary declaration in the network scope (own token class; hover shows g22 : BOOL and its producer); backtick text is checked as ST; .ENO is BOOL; R_EDGE/F_EDGE are builtins typed BOOL→BOOL; => v is a positional output; EN := is valid on any call; PARALLEL is a builtin; value; is a statement. LET, isEnBinding and parseEnEnoIf go. collectVoidCallTargets, isBoxOutput and checkHoles learn the => v pin form and .ENO: ??? := PRG_void_callee(); may now be PRG_void_callee(EN := , => ???);, and the recorded false positive must not return. Label diagnostics follow the recorded builds (census 1.15). Every new token is a format rule, never an LSP-only compiler message.

Migration from v1

v2 shipped as one swap — writer, reader, gate, drivers and LSP together, with no dual reader and no translator — and MATERIALIZATION 3 marks it. The number is stated on every library manifest a pull writes (MATERIALIZATION 3, LibraryManifest.Materialization): the one file every pull writes that can carry a format number, so it names the whole workspace.

  1. Push pending graphical edits before upgrading. The first pull after the upgrade re-materializes every graphical body (its text changed, so its version did) and every library manifest (the bump changes it). An un-pushed v1 edit meets the new text in git's merge, and v1 text can never be pushed afterwards — the push refuses it with NETWORK_PARSE, and by then a re-pull changes nothing. The merge is not always a conflict: an edit next to lines the re-materialization left alone merges cleanly, and when it brought v1 constructs with it (a whole NETWORK 3 LD, a LET) the clean result is a hybrid body. So the pull judges every body it merged and names each file that still holds v1, with the one resolution that works: in a conflict, take the IDE's side (volt merge --resolve <path> --use-theirs), redo the edit on the v2 text, then volt merge --continue; after a clean merge, take the IDE's version (git checkout volt/ide -- src/<path>), redo the edit and commit.
  2. Ship the CLI, the LSP and the extension together. The volt-vscode bundle carries its own LSP and can lag the CLI. The LSP compares the workspace's MATERIALIZATION with its own and names a mismatch once, on the manifests, instead of flagging every graphical body: library-stale when an older Volt pulled the workspace ("run volt pull"), materialization-newer when a newer one did ("update the language server"). A workspace with no library manifest states no number, and a v1 body there keeps its own re-pull finding.
  3. One re-materialization diff per project. The bump's pull rewrites the graphical bodies and the library manifests in the workspace and nothing else, and writes nothing to the IDE: its networks change only when a push carries an edit.
