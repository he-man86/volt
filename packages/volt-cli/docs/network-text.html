Network text

The FBD/LD source form: a literal transcript of the vendor's network model (NWL). One statement per top-level NWL item, nested where the vendor nests, and a name only where the vendor names something (a Demux's VarId). The writer is NetworkTextWriter, the reader NetworkTextReader and the push gate NetworkTextGate, all in Volt.Engine/Format/Network/; the LSP ports the reader. Where a rule rests on a measurement, the census or DIALECT entry is named.

  • Every statement ends with ;, END_IF; and END_EXECUTE; included. A ; that closes nothing is the empty item.
  • Parentheses are structural: every pair is one box — a group's, or a call's argument list. A redundant pair (((a AND b)) as a group) is refused, never read as grouping.
  • Edges are flags, R_EDGE(x) / F_EDGE(x), never an R_TRIG box. With a negation the one order is R_EDGE(NOT x): the vendor negates first (census 1.14, DIALECT N17).
  • Coils are :=, S=, R= with ExST's level semantics (set or reset on every scan the value is TRUE), chained when one item drives several coils.
  • Wires are declared in a per-network VAR_TEMP … END_VAR, typed from their producer.
  • Pull never throws. A network whose trees hold a fact the text cannot spell is shown as its header, its comment and the one line UNSUPPORTED "<shape>";; only what a header cannot carry hides the whole body under the marker. Push refuses by name.

How close to NWL

NWL stores a network as ordered top-level items, each a tree whose children belong to their consumer; the only named intermediate is a Demux's VarId. So: one statement per top-level item, nested expressions for owned subtrees. Single-consumer producers are inline because NWL holds them inline.

The writer's per-network state is the VarId→name map and the set of wires already defined; the reader's is the wire set its VAR_TEMP declares. Nothing is hoisted, minted or reordered. A fact the writer cannot spell is a refusal by name (NetworkUnrepresentableException): the push gate reports it, and the pull render (WritePulled) turns one met in a network's trees into that network's UNSUPPORTED line.

Grammar

body        = line , NL , { network } ;
line        = "IMPLEMENTATION" , ( "FBD" | "LD" ) ;                    (* the first line; case and spacing free *)
network     = header , NL , { comment } , ( unsupported | { wires | statement } ) , "END_NETWORK" ;
header      = "NETWORK" , [ "LABEL:" , name ] , [ "TITLE:" , title ] , [ "DISABLED" ] ;   (* ends at its newline; fields in any order *)
unsupported = "UNSUPPORTED" , '"' , phrase , '"' , ";" ;              (* the network's only line *)
wires       = "VAR_TEMP" , { decl } , "END_VAR" ;                     (* canonically one, before the first statement *)
decl        = wire , { "," , wire } , ":" , type , ";" ;            (* type read off the producer *)
title       = '"' , { char - '"' - "$" - NL | "$N" | "$R" | '$"' | "$$" } , '"' ;   (* ST's string escapes *)
comment     = "//" , { char - NL } , NL ;                           (* ends at its newline *)
wire        = ( "g" | "G" ) , digit , { digit } ;                    (* the digits are the VarId *)

statement   = ( assign | jump | cond | value ) , ";" ;              (* ONE per NWL item *)
cond        = "IF" , value , "THEN" , jump , ";" , "END_IF" ;
assign      = lvalue , op , { lvalue , op } , value ;                (* a declared wire alone with ":=" = a Demux *)
op          = ":=" | "S=" | "R=" ;                                (* "S =" is "S=" after a target *)
jump        = "JMP" , name | "RETURN" ;                              (* any identifier after JMP is the label *)

value       = edge | [ "NOT" ] , core | (* empty *) ;
edge        = ( "R_EDGE" | "F_EDGE" ) , "(" , [ "NOT" ] , core , ")" ;   (* a flag, not an FB *)
core        = group , { pragma } | call , { pragma } , [ ".ENO" | "." , name ] | execute , { pragma } , [ ".ENO" ]
            | nested | parallel | operand ;                          (* ".name": a main output not slot 0 *)
group       = "(" , value , operator , value , { operator , value } , ")" ;   (* one operator kind *)
nested      = "(" , lvalue , op , { lvalue , op } , value , ")" ;  (* S2: an assign below the top level *)
call        = ( "???" , ":" , name | head ) , "(" , [ pin , { "," , pin } ] , ")" ;   (* "()" = no input slot *)
head        = boxtype | instance | backtick ;                        (* NOT(…) is the NOT box; `SUPER^` the base FB *)
pin         = [ [ "NOT" ] , name , ":=" ] , value | name , "=>" , lvalue | "=>" , [ lvalue ] ;   (* NOT name: a negated pin *)
pragma      = "{" , member , { "." , member } , ":=" , ( literal | "[" , [ literal , { "," , literal } ] , "]" ) , "}" ;
literal     = st-string | integer | "TRUE" | "FALSE" | name ;     (* ST's literals; a string never spans a line *)
execute     = "EXECUTE" , [ "(" , "EN" , ":=" , value , ")" ] , NL , st-lines , "END_EXECUTE" ;
parallel    = "PARALLEL" , "(" , [ "MODE" , ":=" , mode , "," ] , [ "IN" , ":=" , value , "," ] , value , { "," , value } , ")" ;   (* MODE only off its default *)
operand     = token | backtick ;
lvalue      = token | backtick ;
backtick    = "`" , { char - "`" } , "`" ;
operator    = "AND" | "OR" | "XOR" | "+" | "-" | "*" | "/" | "MOD"
            | ">" | "<" | ">=" | "<=" | "=" | "<>" ;      (* FbdOperators.cs *)
  • Terminators: every statement ends with ; — IF a THEN JMP Done; END_IF; and END_EXECUTE; too. That ; belongs to its statement; only a ; that closes nothing is the empty item, written on its own line.
  • Parentheses are structural: a pair is a group's (it holds an operator), a call's (it follows a head) or an assignment's (a target and a storage operator open it: (t := v), S2 — (R = x) stays a comparison, since storage is decided after a target). After NOT, a pair holding an operator is a group under the modifier; any other pair is the NOT box's argument list. After an operator word (AND, MOD, …) the same: a pair holding an operator at its own depth is a group, so the word was the operator after an empty slot (( AND (x OR y))); any other pair is the word's argument list (AND(EN := go, a, b)). Spacing plays no part. A pair that is neither is refused.
  • Call heads: an operator or function box's head is its BoxType verbatim — bare when it is one name and no word of the text other than the operators' own (ADD, MOVE, AND, GE, MAX, NOT), else between backticks (a POU named Network is called `Network`(x)). An operator type spelled otherwise than the table (and) keeps its spelling in call form, never infix. An FB box's head is its instance. The FB's type is taken from the instance's declaration, and a declaration names a NAME — so an instance whose text is an expression (fbs[1], census 1.12) has no spelling, and a push of `fbs[1]`(IN := a) is refused rather than read as a function named fbs[1]. The one such instance the scope answers is `SUPER^`: the base the POU's (or its owner's) EXTENDS names (S5). A function box named like an instance in scope has no spelling either: its head would read back as that instance.
  • lvalue: an assign target or a => v pin is a token or a backtick, by the same rule as an operand (`arr[i + 1]` := x;); a literal target is backticked. A bare => is an output slot connected to nothing; a named F => needs a target.
  • Words of the text (NOT, AND, PARALLEL, EXECUTE, JMP, VAR_TEMP, UNSUPPORTED, …) at operand or target position are backticked. PARALLEL, R_EDGE and F_EDGE as a POU or FB instance name are refused.
  • Wire names: the writer names a wire g<VarId>, or the lowest free g<n> when that matches, case-insensitively, a name in scope (POU variables, globals, the owning FB's members from a method, POUs, instances) or a word the network spells. The reader takes any declared g<digits>: in its network a wire resolves before a same-named variable.

Newlines and whitespace

Newlines are significant in exactly three places: the header ends at its newline, each // comment line ends at its newline, and an EXECUTE body runs from the newline after EXECUTE[(…)] to the first line whose first word is END_EXECUTE. A header is only the whole word NETWORK at a line start outside an EXECUTE body (NetworkState := 1; is not one). So a line after NETWORK that starts DISABLED :=, TITLE := or LABEL := is a statement, never a header field. Elsewhere, whitespace and newlines are layout — except inside backticks, TITLE strings, comments and EXECUTE bodies. S= / R= are the word and =, so x S = a; is x S= a; and (R=x) compares a variable R: after a target the pair is the storage operator, inside a group it is a comparison. A CR LF line ending is layout everywhere, in a comment and an EXECUTE body included; a lone CR is refused.

Body line. Every body states its language on the line that ends its declaration (ImplementationMarker in the engine, implementation-line.ts in the LSP): IMPLEMENTATION ST over ST, IMPLEMENTATION FBD or IMPLEMENTATION LD over network text, one per body — an FB with an ST body and an LD method carries IMPLEMENTATION ST on the FB and IMPLEMENTATION LD on the method; a property's two accessors carry one each. The stated language is the one signal for which reader runs; network text under ST, ST under LD, or a missing language is refused by name. The marker, wherever this page sends a body to it, is IMPLEMENTATION FBD UNSUPPORTED / IMPLEMENTATION LD UNSUPPORTED with nothing under it: no implementation is shown, the pull message names the item and the shape network text has no spelling for, the declaration stays editable, and a push never writes that body. CFC, SFC and IL bodies are always IMPLEMENTATION CFC|SFC|IL UNSUPPORTED, and a body in a language Volt has never seen — an unknown view, body aspect or archive root — is hidden the same way under the vendor's own name for it, upper case (IMPLEMENTATION NWL UNSUPPORTED for a network body that states no view), so its item still pulls. An ABSTRACT member with no code — a METHOD, or a GET/SET under PROPERTY ABSTRACT, whose body is empty or missing — states IMPLEMENTATION NONE, alone, nothing under it, on both vendors and whatever object holds it (DIALECT C2n): no language, read by neither reader; a push writes an empty body where the object has a slot and nothing where it has none, and a create of it is accepted. Code under ABSTRACT (both compilers refuse it: "must not contain any statements"), NONE without ABSTRACT (unless the IDE already holds it so, C2l), and NONE at a POU's own body or an action are refused by name; a comment-only abstract body stays IMPLEMENTATION ST. IMPLEMENTATION NONE UNSUPPORTED is another line: a hidden body of a language spelled NONE. A build without VOLT_GRAPHICAL=1 hides every LD and FBD body under the marker, with the reason "LD and FBD are not enabled in this build". Editing the line between LD and FBD changes the body's view: both drivers write it.

A network the text cannot spell is shown, not its body hidden. Where a network's TREES hold a fact this page has no spelling for — a vendor-reader refusal or a writer refusal met inside it — the network keeps its header and its comment, and its trees are the one line UNSUPPORTED "<shape>";, the shape the refusal names as a quoted phrase: 

NETWORK LABEL: L1 TITLE: "Calc"
  // why
  // it is
  UNSUPPORTED "a flag on a box input pin";
END_NETWORK

The line is its network's only statement (no wire block, nothing before or after it); the LSP reports nothing inside such a network. Pushed back unchanged it pairs with the live network and is kept exactly as the IDE holds it; its header (TITLE, LABEL, DISABLED, the comment) can be edited; deleting the whole network removes it. An edited line, or one in a new network, holds nothing to build from and is refused (NETWORK_UNSUPPORTED). What a network's HEADER cannot carry (a label that is no identifier, a title or comment the IDE does not store, a comment line ending in a lone carriage return) has no line to stand on and hides the body under the marker. UNSUPPORTED is a word of the text: an operand spelled like it is backticked.

A push pairs networks by their TEXT, never by position (NetworkPairing, both vendors). Each live network is rendered as the pull renders it, and the live and pushed lists are aligned in order at the least cost of what the push then does: a network whose whole text is equal is kept — the vendor object is not touched; one whose header alone changed is rewritten in its slot with its trees kept; one whose trees changed is rebuilt in its slot; a live network nothing pairs with is removed, a pushed one inserted (on TwinCAT: the IDE's one-network import, spliced in where it stands). So inserting or deleting a network rebuilds no other, and a network no push can build (fb(…).name, an enabled comparison a consumer reads — DIALECT N21) is refused only when its own text changed. A changed network that holds a symbol comment on an operand is refused too (NETWORK_UNSUPPORTED): the text does not spell symbol comments, so a rebuild would erase them. Nothing the text does not show is erased by a pairing (gate 1b-4). A live network shown as its UNSUPPORTED line is never rewritten from other trees — replacing its line under the same header, or emptying it, is a removal plus an insertion. A live network holding what the text does not show (its UNSUPPORTED line, or a symbol comment) may be deleted, but not in a push that also inserts a network — pairing by text cannot tell a deletion from a move or a rewrite, and the inserted network, built from the text, would not carry it — and not where another network that stays shows the same text (which of the two went is not in the text). Each is refused naming the network (NETWORK_UNSUPPORTED).

Constructs

One example per production. Each is a writer golden or reader test in test/Volt.Engine.Tests/format/network/. Most are FBD: ladder uses the same productions. Outside a whole network, statements are shown without their two-space indent.

Header and comment

NETWORK LABEL: Done TITLE: "Tray $"A$" ready" DISABLED
  // Indented notes keep their indentation:
  //     step 1 — wait for the tray
  //
  // // a line that itself starts with two slashes
  VAR_TEMP g0 : BOOL; END_VAR
  g0 := TRUE;
END_NETWORK

The header fields are written in one order (LABEL, TITLE, DISABLED); any order is read, and a field given twice is NETWORK_PARSE. The comment is the network's one Comment: its // lines sit between the header and the wire block (or the first statement), and a // after a statement is NETWORK_PARSE — NWL has no per-item comment. Per line, the // and one following space are syntax; the rest, leading indentation and a leading // included, is text. An empty comment line is //; a blank line between // lines and the indentation before // are layout. A title and the comment as a whole are read as the drivers store them (NetworkText.Stored): trailing whitespace at their end, an empty title and a closing empty // line are trimmed away.

Wires — the one named thing

NETWORK TITLE: "DONE Network 1: Activating/deactivating MID-S/Trayfiller"
  VAR_TEMP g0, g1 : BOOL; END_VAR
  g0 := TRUE;
  g1 := (g0 AND NOT Mach1_Safety.Status.Custom_ATF_Disabled);
  Mach1_AuxData.TrayfillerActive := g1;
  HMI_Var.TrayfillerActive := g1;
  Mach1_AuxData.MIDS_Active := (g0 AND TRUE);
END_NETWORK

Mach1_MIDS network 0, the left rail. g0 := and g1 := are Demux items with an Input (each a top-level item); the two bare g1 are nested references. Five statements for five items. A consumer that is not a declared wire (a sink) is an ordinary coil.

The block. The writer gives a network with a Demux exactly one VAR_TEMP … END_VAR, after its // lines and before its first statement, and a network without one none. The reader takes more: a second block, a block after a statement (a wire is a wire from its declaration on, in text order), an empty block, and a declared wire nothing defines or uses — all layout, read into the same model and written back canonically on the next pull. One limit: a late block may not declare a name the network already read as a variable (NETWORK_DUPLICATE_NAME), because the one spelling would then be the variable before the block and the wire after it. VAR_TEMP because a wire's value exists only while the network evaluates; per network because VarIds are. Canonically one line; the reader also takes it across lines (VAR_TEMP / g22 : BOOL; / END_VAR), as ST does. Wire-ness comes from the declaration only — never use count, never a prefix — matched case-insensitively. g<digits> carries the VarId, so a wire keeps its name (C9). The writer emits items in vendor order and never reorders; a vendor order that references a wire before defining it has no spelling.

The type comes from the producer, one rule for FBD and LD, applied by the writer to declare and by the reader to check. The Demux holds no type, so the text may not invent one. The vendor's stored output type of the connected slot comes first (a bitwise AND on WORDs is a WORD). Otherwise BOOL: a comparison, TRUE/FALSE, an edge, .ENO, PARALLEL, an AND/OR/XOR/NOT box (BOOL or the bit-string type the text declares), and a leaf whose EVERY use is boolean — an EN, a PARALLEL, a jump condition, an edge on the reference, and in ladder a coil or contact (census 1.17). A leaf feeding a data pin, and a data box with no stored type, say nothing: on pull the wire has no spelling (never guessed), and a hand-written declaration is taken as written. The gate checks a declared type against what the producer says and refuses a mismatch by name — the IDE has no field that would keep it.

Assignment — coils

lamp := x;

A plain coil, then ONE assign with three coils in OutputItemList order (the chained form, one target per line canonically). S=/R= are ExST's level-triggered set and reset, and every target takes the value at the end of the chain. Negated and edge coils are not spelled (above).

An FB call with named input and output pins; a function with a named output pin, assigned; a named function box; a top-level box with no input slot. The FB's type comes from the instance's declaration — so the writer and the reader resolve an instance through the same declarations, and an instance they do not name (SUPER^) has no spelling rather than read back as a function.

An unconnected pin is an empty position, never a token: pin 0 of a MUL box, named pins with nothing on them, a leading and a trailing positional slot, a lone empty slot (named, since MOVE() is a box with no input slot), a rung nothing drives, and the empty item. A flag on an empty slot has no spelling: NETWORK_UNSUPPORTED on push.

Infix groups and the NOT box

out := ((a AND b) OR c);
out := NOT a;
out := NOT (a AND b);
out := NOT(a);
out := NOT((a AND b));

A group is one operator box. NOT a is the negation modifier on an operand; NOT (a AND b) the modifier on an AND box's output; NOT(a) the NOT box; NOT((a AND b)) the NOT box around an AND box. Spacing plays no part: each pair of parentheses is exactly one box.

When a box is infix (NetworkSpelling.IsInfix, census 1.5): an operator of the table, its type spelled in upper case, at least two inputs, no EN, no instance, no output pin, no consumer connected by its ENO, and formals that are absent or the operator's defaults (IN1, IN2, …) — the two are one text, and the driver writes the defaults. Anything else is call form.

Edges

MOVE(EN := R_EDGE(bStart), 1, => nMode);
out := F_EDGE(NOT x);
lamp := R_EDGE((a AND b));

A rising edge on MOVE's EN (the pro2193 ActuatorFB shape); a falling edge of a negated operand; an edge on an AND box's output — the outer pair is R_EDGE's, the inner the group's. The argument carries no modifier but one NOT, which is the node's own negation: the vendor negates first, on an operand and on a box alike, so R_EDGE(NOT x) is Negation+Rtrig and NOT R_EDGE(x) is refused (census 1.14, DIALECT N17; measured on CODESYS — TwinCAT's order is not, so its driver refuses R_EDGE(NOT x) on push and shows it as its network's UNSUPPORTED line on pull). A Parallel or a wire reference holds no flag at all (N20): R_EDGE(g3) is refused, and the edge goes on the wire's producer. And R_EDGE(NOT(a)) is an edge on the NOT box — its pair holds no operator, so it is NOT's argument list, as everywhere; nested edges and rising+falling on one operand are refused by name.

EN, ENO and output slots

MOVE(EN := a, b);
MOVE(EN := c, 0, => Status);
AND(EN := go, a, b, => out);
GT(EN := SUB(EN := rung, light, deviation, => diff).ENO, sensor, diff, => out);

A MOVE with EN wired and its output going nowhere; a MOVE writing its own result pin; an operator box in call form because it has EN; and the EN-chained FBD pair from SideCorrection — a SUB's ENO enabling a GT, each writing its own pin.

The slot rule. The model carries each output's slot index and, on a consumed box, the slot its consumer is connected to; the text spells that stored slot:

  • ENO is never an => slot. It is only ever .ENO.
  • A consumed box connected by its ENO output says .ENO, and that wins where ENO is also the main output (every box whose outputs start with ENO), so one model has one text; connected by a main output that is not ENO it has no suffix. Census 1.6 (DIALECT N16) found no other: every export connection that names a slot names MainOutputIndex (338 checked, none disagreeing), and that slot IS the ENO output exactly when the box has one. Any other connection slot has no spelling. A pushed consumer without a suffix on a box the IDE gives an ENO main output is refused, naming the box — the mirror of .ENO on a box with no ENO.
  • The text does not say WHICH slot the main output is, so it reads it by rule: slot 0, and for an AND/OR/XOR/NOT box no stored slot where it stores no output (the plain box, census 1.6) and slot 0 where it stores one — the editor's form, (a AND b){OutputParam.Names := ['']} (S1, the pragma): one output slot per stored name. The rule is the same for a group and a call: (a > b) and GT(a, b) read to one box, connected by slot 0, and the slot never decides infix — except ENO: a group has no suffix position, so an operator box consumed by its ENO is a call, out := ADD(a, b).ENO;, never (a + b), which is the same ADD consumed by its data output. A box the rule would misread is spelled otherwise or refused: a main output stored as another slot (1 on 3 Lenze call boxes) is spelled by its NAME, below; a consumed box whose connection slot was never read is refused. Renumbering its pins instead would wire them to other slots on push.
  • fb(…).name: a box consumed by a main output that is not the slot the rule reads — Lenze FirstErrorCapture's GVL_FirstErrCapture.xFirstErrorBit := fbFirstErrCapture(…).xErrorActive;, main output 1. The name is the box's own stored output name for that slot (OutputParam.Names), so no library signature is needed, and it is written only where the main output is not slot 0, so no other text changes. .name states no slot: a positional => v beside it is refused (name the pin), as are .name on a box nothing consumes, on a bit operator (which stores no main output) and .EN. A stored name that is a word of the text (Execute would open an EXECUTE body) is not written: the network is shown as UNSUPPORTED "a named main output spelled like a text word";. Such a box is shown and kept, never built: MainOutputIndex is read-only on a box a push constructs (DIALECT N21), so a push that CHANGES its network is refused on CODESYS, naming the network and the output; on TwinCAT it is unmeasured (no TwinCAT project holds one) and refused the same way. A network whose text is unchanged is kept as the IDE holds it (the pairing).
  • Positional => v pins fill the remaining output slots in order, skipping the connected one. A named F => v goes to slot F.
  • .ENO means "connected to the ENO output", never "the box has EN" — the two are independent (census 1.6). An enabled comparison has EN and no ENO, and its consumer reads its one data output: out := GT(EN := c, a, b); (40 boxes in the corpora). An FB may declare ENO without EN (Lenze Dryer), and an Execute box has no output but ENO, so END_EXECUTE.ENO needs no EN (census 1.11). The push refuses .ENO on a box the IDE gives no ENO output.

So coil := MOVE(EN := rung, src, => dst).ENO; is "dst gets src, coil gets ENO": a MOVE showing EN/ENO has ENO as its main output, and its consumer reads ENO (census 1.6). GT(ADD(EN := x, a, b), c) would claim GT reads ADD's data output, which no measured ADD with EN is connected by; the push refuses what the IDE's box cannot connect.

Members — the pragma

out := (a AND b){OutputParam.Names := ['']}{OutputParam.Types := ['BOOL']};
t1(IN := go){OutputParam.Names := ['Q', 'ET']}{OutputParam.Types := ['BOOL', 'TIME']};

Network text is the NWL tree one to one for every member that is not a measured editor cache (openspec ld-fbd-coverage, design "1b.2", "2.3"). A member the statements above do not spell is a pragma directly after its node — one {Member := value} per member, the value one of ST's literals (a single-quoted string with ST's $ escapes, an integer, TRUE/FALSE, an enum word) or a bracketed list of them. Each member has a DERIVATION, what the text already implies, and the pragma is written only where the stored value differs from it — so a body whose members are all their derivations reads as before. A text read keeps a spelled value; a push writes the stored value, else the derivation. A pragma naming a member the table does not hold, a value of another kind, or one member twice is refused by name (NETWORK_UNSUPPORTED, NETWORK_BAD_EXPRESSION, NETWORK_DUPLICATE_NAME).

The gate

Body language (the IMPLEMENTATION line matches the IDE's view), then parse, then write: a body that reads into a complete model the writer can spell is pushed, in any spelling — canonical form is not a refusal. The written text is the body's canonical form, which the next pull shows. A model the writer cannot spell is refused NETWORK_UNSUPPORTED, at the construct that holds the fact. A separate test oracle (NetworkModelOracle) checks Read(Write(m)) ≅ m over every vendor-read fixture: the check that sees pull-side loss. Its one equivalence is absent ≡ default formals.

Layout after a push. The writer has one canonical layout. After a successful push the CLI records the IDE's re-materialized — canonical — text as volt/ide and brings the working tree to it, as a formatter would. A hand layout therefore lasts until its push and never reappears as an IDE-side change on a later pull; an item the push did not touch is not re-fetched. Only the same program is adopted: other layout, or the canonical spelling of a body pushed in another (both texts read, in the body's own declarations, to one canonical text). An IDE that holds a pushed item as another program is not adopted, so the working tree keeps the pushed text, the push names the item, and the next pull brings the IDE's text in as the IDE-side change it is.

The language server

The LSP's network parser (volt-lsp-iec/src/frontend/syntax/network/parser.ts) is a port of the reader: the same tokens, the same NETWORK_* finding at the same token, so what the editor underlines is what the push refuses. Unlike the bridge, it keeps the statements read before a finding, so hover and the type checks still see them. A VAR_TEMP wire is a declaration in the network's scope, with its own semantic-token class; hovering one shows g22 : BOOL and its definition. Nothing is reported inside an UNSUPPORTED network. Label diagnostics follow the recorded builds (census 1.15); every token of the text is a format rule, never an LSP-only compiler message.
