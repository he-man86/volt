Network text

The FBD/LD source form: the vendor's network model (NWL), written the way the drawing reads. One rule above all: a box is its NAME — what CODESYS writes on the box (a ADD b, MOVE b => a) — and :=, S=, R= are coils only. One ; is one NWL item, a name exists only where the vendor names something (a split point's VarId), and every text is exactly one tree. The writer is NetworkTextWriter, the reader NetworkTextReader and the push gate NetworkTextGate, all in Volt.Engine/Format/Network/; the LSP ports the reader. The accepted and refused texts are one committed case set (below) both read. 

NETWORK TITLE: "Start the motor"
  split1 := TRUE;
  MOVE 0 => speed EN split1;
  fault R= split1 AND NOT test;
  split2 := split1 AND auto;
  run := lamp := motor := split2;
  MOVE setpoint => speed EN (split2 BRANCH (NOT slow,
                                            (setpoint LE 40 EN slow))) AND NOT cleaning;
  Scale(iEN := split1, iRPM := speed, oSpeed => drive);
END_NETWORK

A network as the pull writes it.

  • Boxes are words, infix: AND OR XOR ADD SUB MUL DIV MOD GT GE EQ NE LE LT and MOVE. ST's symbols + - * / > < >= <= = <> are no network text.
  • The enable is EN after the box; its ENO is read on a later line by the word ENO, from a line that ends without ;.
  • Brackets mark three things: a word box or a parallel as another word's operand, an enabled comparison used as a value, a nested assignment. Nothing else is bracketed, and a redundant bracket is refused.
  • Split points are split<VarId>, defined once before their references, with no declaration and no type. A parallel branch is feed BRANCH (a, b, …).
  • No pragma. A stored member the text does not spell is derived on push, written only where it differs and has a natural spelling, else lost on rebuild — never a {Member := …}.
  • Pull never throws. A network whose trees hold a fact the text cannot spell is shown as its header, its comment and the one line UNSUPPORTED "<shape>";; only what a header cannot carry hides the whole body under the marker. Push refuses by name.

How close to NWL

The writer's per-network state is the set of splits already defined and, per item, the open lines its ENOs take; the reader's is the same. Nothing is hoisted, minted or reordered. A fact the writer cannot spell is a refusal by name (NetworkUnrepresentableException): the push gate reports it, and the pull render (WritePulled) turns one met in a network's trees into that network's UNSUPPORTED line.

Grammar

body        = line , NL , { network } ;
line        = "IMPLEMENTATION" , ( "FBD" | "LD" ) ;
network     = header , NL , { comment } , ( unsupported | { item } ) , "END_NETWORK" ;
header      = "NETWORK" , [ "LABEL:" , name ] , [ "DISABLED" ] , [ "TITLE:" , title ] ;   (* in that order; ends at its newline *)
unsupported = "UNSUPPORTED" , '"' , phrase , '"' , ";" ;
title       = '"' , { char - '"' - "$" - NL | "$N" | "$R" | '$"' | "$$" } , '"' ;          (* exact: TITLE: "" refused *)
comment     = "//" , [ " " ] , { char - NL } , NL ;

item        = { open } , statement , ";" ;                          (* ONE per NWL item *)
open        = root , NL ;                                           (* a line without ";": its root's ENO is read below *)
statement   = assign | split | jump | root | (* empty *) ;
assign      = coil , { coil } , ( value | "NOT" ) ;                (* chained coils, one value; NOT alone negates the empty one *)
coil        = target , op | modifier , target , ":="
            | ( "JMP" , name | "RETURN" ) , ( ":=" | "S=" ) ;      (* a jump and a return are coils *)
modifier    = "NOT" | "R_EDGE" | "F_EDGE" ;
op          = ":=" | "S=" | "R=" ;
split       = "split" , digits , ":=" , value ;                    (* the digits are the VarId; no leading zero *)
jump        = "JMP" , name | "RETURN" ;                            (* alone on the rail *)
root        = level , [ [ "NOT" ] , "EN" , [ value ] ] | execute ; (* an enabled box is its line's root *)

value       = [ level ] ;                                           (* a slot: one box, unbracketed, or empty *)
level       = word-box | parallel | operand-or-call ;
word-box    = operand , word , operand , { word , operand } , { "=>" , target } ;   (* one word kind per level *)
            | "MOVE" , operand , { "=>" , target } ;
parallel    = [ feed ] , "BRANCH" , "(" , [ value ] , "," , [ value ] , { "," , [ value ] } , ")" , [ "SHORTCIRCUIT" ] ;
operand     = [ "NOT" ] , ( atom | "(" , bracketed , ")" ) | edge ;
bracketed   = word-box | parallel                                   (* 1. an operand of another word *)
            | level , "EN" , [ value ]                              (* 2. an enabled comparison as a value *)
            | assign | split ;                                     (* 3. a nested assignment, or definition *)
edge        = ( "R_EDGE" | "F_EDGE" ) , "(" , [ "NOT" ] , value , ")" ;
atom        = token | backtick | "ENO" | "split" , digits | call ;
call        = ( "???" , ":" , name | head ) , "(" , [ pin , { "," , pin } ] , ")" , [ "." , name ] ;
pin         = [ [ modifier ] , name , ":=" ] , value | name , "=>" , target | "=>" , [ target ] ;
execute     = "EXECUTE" , [ "EN" , [ value ] ] , NL , st-lines , "END_EXECUTE" ;
target      = token | backtick ;
backtick    = "`" , { char - "`" } , "`" ;
word        = "AND" | "OR" | "XOR" | "ADD" | "SUB" | "MUL" | "DIV" | "MOD"
            | "GT" | "GE" | "EQ" | "NE" | "LE" | "LT" ;
  • Words of the text (case-insensitive): EN ENO BRANCH SHORTCIRCUIT JMP RETURN EXECUTE END_EXECUTE NOT R_EDGE F_EDGE NETWORK END_NETWORK UNSUPPORTED, every box word and the pattern split<digits> (P1). A variable, pin, FB, global or enum value spelled like one is backticked — a reference never falls back to a variable: y := `ENO`;, x := `split5`;, f(`branch` := b). IF THEN END_IF LET VAR_TEMP PARALLEL are no words.
  • Lines (P2). Outside brackets a line break ends the line unless the line ends with a word that cannot end it — an infix word, BRANCH, =>, :=, S=, R=. Inside brackets a line break is layout. So EN at a line's end is always the empty enable, and the writer wraps after AND, never before it.
  • Literals are bare: -1 (the minus touching the digit), 'Recipes', T#1S. - 1, -x and +1 are refused.

Newlines and whitespace

Beside P2's line rule, newlines are significant in three places: the header ends at its newline, each // comment line ends at its newline, and an EXECUTE body runs from the newline after the EXECUTE line to the first line whose first word is END_EXECUTE. A header is only the whole word NETWORK at a line start outside an EXECUTE body. Elsewhere whitespace is layout — except inside backticks, TITLE strings, comments and EXECUTE bodies. A CR LF line ending is layout everywhere; a lone CR is refused.

Body line. Every body states its language on the line that ends its declaration (ImplementationMarker in the engine, implementation-line.ts in the LSP): IMPLEMENTATION ST over ST, IMPLEMENTATION FBD or IMPLEMENTATION LD over network text, one per body — an FB with an ST body and an LD method carries IMPLEMENTATION ST on the FB and IMPLEMENTATION LD on the method; a property's two accessors carry one each. The stated language is the one signal for which reader runs; network text under ST, ST under LD, or a missing language is refused by name. The marker, wherever this page sends a body to it, is IMPLEMENTATION FBD UNSUPPORTED / IMPLEMENTATION LD UNSUPPORTED with nothing under it: no implementation is shown, the pull message names the item and the shape network text has no spelling for, the declaration stays editable, and a push never writes that body. CFC, SFC and IL bodies are always IMPLEMENTATION CFC|SFC|IL UNSUPPORTED, and a body in a language Volt has never seen — an unknown view, body aspect or archive root — is hidden the same way under the vendor's own name for it, upper case (IMPLEMENTATION NWL UNSUPPORTED for a network body that states no view), so its item still pulls. An ABSTRACT member with no code — a METHOD, or a GET/SET under PROPERTY ABSTRACT, whose body is empty or missing — states IMPLEMENTATION NONE, alone, nothing under it, on both vendors and whatever object holds it (DIALECT C2n): no language, read by neither reader; a push writes an empty body where the object has a slot and nothing where it has none, and a create of it is accepted. Code under ABSTRACT (both compilers refuse it: "must not contain any statements"), NONE without ABSTRACT (unless the IDE already holds it so, C2l), and NONE at a POU's own body or an action are refused by name; a comment-only abstract body stays IMPLEMENTATION ST. IMPLEMENTATION NONE UNSUPPORTED is another line: a hidden body of a language spelled NONE. A build without VOLT_GRAPHICAL=1 hides every LD and FBD body under the marker, with the reason "LD and FBD are not enabled in this build". Editing the line between LD and FBD changes the body's view: both drivers write it.

A network the text cannot spell is shown, not its body hidden. Where a network's TREES hold a fact this page has no spelling for — a vendor-reader refusal or a writer refusal met inside it — the network keeps its header and its comment, and its trees are the one line UNSUPPORTED "<shape>";, the shape the refusal names as a quoted phrase: 

NETWORK LABEL: L1 TITLE: "Calc"
  // why
  UNSUPPORTED "a flag on a box input pin";
END_NETWORK

The line is its network's only statement; the LSP reports nothing inside such a network. Pushed back unchanged it pairs with the live network and is kept exactly as the IDE holds it; its header can be edited; deleting the whole network removes it. An edited line, or one in a new network, holds nothing to build from and is refused (NETWORK_UNSUPPORTED). What a network's HEADER cannot carry (a label that is no identifier, a title or comment the IDE does not store) has no line to stand on and hides the body under the marker.

A push pairs networks by their TEXT, never by position (NetworkPairing, both vendors). Each live network is rendered as the pull renders it, and the live and pushed lists are aligned in order at the least cost of what the push then does: a network whose whole text is equal is kept — the vendor object is not touched, every stored member with it; one whose header alone changed is rewritten in its slot with its trees kept; one whose trees changed is rebuilt in its slot; a live network nothing pairs with is removed, a pushed one inserted. So inserting or deleting a network rebuilds no other, and a network no push can build (fb(…).name, an enabled comparison a consumer reads — DIALECT N21) is refused only when its own text changed. A changed network that holds a symbol comment on an operand is refused too: the text does not spell symbol comments, so a rebuild would erase them. Nothing the text does not show is erased by a pairing (gate 1b-4): a live network holding what the text does not show (its UNSUPPORTED line, a symbol comment) may be deleted, but not in a push that also inserts a network, and not where another network that stays shows the same text. Each is refused naming the network.

Constructs

One example per rule; each is a case of the shared case set or a writer golden in test/Volt.Engine.Tests/format/network/. Outside a whole network, statements are shown without their two-space indent.

Header and comment

NETWORK LABEL: Done DISABLED TITLE: "Tray $"A$" ready "
  // Indented notes keep their indentation:
  //     step 1 — wait for the tray
  //
  // // a line that itself starts with two slashes
  out := a;
END_NETWORK

The fields are LABEL, DISABLED, TITLE, in that order (P10); another order, a field given twice and TITLE: "" (no TITLE is the empty title) are NETWORK_PARSE. The title is exactly the IDE's, a trailing space included. The comment is the network's one Comment: its // lines sit between the header and the first item, and a // after a statement is refused — NWL has no per-item comment. Per line the // and one following space are syntax; the rest is text, trailing spaces kept. The lines are joined with CR LF; a trailing CR LF in the stored comment is a final bare // line.

Splits — the one named thing

NETWORK TITLE: "Tray ready"
  split0 := TRUE;
  split1 := split0 AND NOT disabled;
  ready := split1;
  lamp := split1;
  active := split0 AND TRUE;
END_NETWORK

A split point is NWL's BoxTreeDemux: one definition node holding the feeder, reference nodes elsewhere, linked by VarId. Its name IS the VarId, split<n> with no leading zeros (B6). It is defined once per network with :=, where NWL holds the definition — its own item, or nested, x := (split1 := a AND b); — and referenced anywhere in the network, above the definition too (that reference reads the previous scan). It is never a coil target, a => target or a call head (P9). Nothing declares it and no type is written: the Demux holds none, and its uses are typed by the feeder. In LD split3 := ; is the left rail (S3b). A bare split5 is always the split; a variable of that shape is backticked, `split5`, so a split beside a declaration of its name is no collision.

Assignment — coils

lamp := x;
run := lamp := motor := start;
first R= ;
NOT lamp := start;
R_EDGE lamp := start;

A plain coil; ONE assign with three coils in OutputItemList order; a coil on the rail (an empty source); a negated coil; an edge coil — a coil's modifier stands before it. S=/R= are ExST's level-triggered set and reset, and every target takes the value at the end of the chain. a := b; is a coil fed by a leaf — no box.

Operator boxes — words (B1)

x := a ADD b;
x := a ADD b ADD c;
x := a ADD (b ADD c);
out := a GT 40;
x := (a AND b) OR c;

One word is one box with as many inputs as it has operands; brackets separate boxes. A level holds one word kind, so a second word is a bracketed box (x := a ADD b MUL c; is refused). SUB, DIV, MOD and every comparison take exactly two inputs: a third is refused (SUB takes 2 inputs) — CODESYS stores the box and its build refuses it, "'-' needs exactly '2' operands" (C3). AND and OR take as many as drawn. Every operator takes at least two: one is refused (ADD takes at least 2 inputs) — both IDEs store it and refuse its build.

MOVE (B2)

MOVE b => a;
MOVE b => a => c;
a := MOVE b;
MOVE (a ADD b) => x;

MOVE is a word with one operand; its target is an output pin, like every box's. Several => are several targets. MOVE is a word, so a word box as its operand is bracketed.

EN — the enable after the box (B3)

MOVE b => a EN c;
x ADD 5 => x EN c;
LIMIT(0, v, 100, => y) EN c;
t1(IN := go, PT := T#1S) EN c;
iRPM MUL 6 => oDrive EN;
MOVE 5 => y NOT EN c;
EXECUTE EN c
x := 1;
  END_EXECUTE;

EN follows the box and enables the box of its level (x ADD f(b) EN c enables the ADD); its tail runs to ;, ), , or the line's end, and is a slot — one box, unbracketed, a parallel included. => comes before EN. A call keeps its output pins inside its brackets. EN with nothing after it is the enable shown and wired to nothing (37 in the corpora). NOT EN c negates the EN pin, EN NOT c the contact feeding it. An enabled box is the root of its line: its value leaves only through => or ENO, so a := MOVE b EN c; and x := a ADD b EN c; are no text (CODESYS hands a coil after an enabled box its ENO, N21).

ENO — open lines (B4, P3)

MOVE 175  => VelUnit EN split329 AND TRUE
MOVE 2000 => DecUnit EN ENO
MOVE 750  => AccUnit EN ENO
MOVE 100  => TorqueLimit EN ENO;

MOVE 860 => AutoSpeed EN split20
StartAuto := ENO;

MOVE 1 => A EN c
MOVE 2 => B EN d
x := ENO AND ENO;

MOVE 1 => x EN c
JMP Done := ENO;

One ; is one NWL item. A line without ; is open: its root's ENO goes to a later line of the item. Each ENO takes the oldest open line above it not yet taken — top to bottom, the ENOs of one line left to right, inside its brackets too — and every open line is taken exactly once. So a chain reads as written, and two ENOs into one box take A, then B. The writer orders lines by level: the ; line's ENOs are the last open lines, in its order; the lines those read come before them, in theirs; and so on, so one tree has one text. A consumed box carries no modifier: its NOT is written at the token, x := NOT ENO;.

Refused: an open line nothing takes; ENO with no open line above it; an open line whose root has no ENO — a coil, a split definition, a jump, a leaf, a parallel, an operator box without EN (MOVE 1 => A has no EN, so no ENO, N21). A call with an ENO and no EN hands its ENO on. An ENO read twice is a split CODESYS stores there: split21 := ENO;. Moving a whole item only reorders items, like moving a rung; moving one line out of a chain is refused, never silent.

Brackets — three things (B5, P4)

x := a ADD (b ADD c);
(split1 AND bSync) BRANCH (a, b);
x := (a GT b EN c);
y := (x := v);
t1(IN := a AND b, PT := T#1S);

A bracket level and every slot — a coil's value, an EN tail, a pin, a call argument, a split definition, a branch — hold one box. Brackets mark exactly: (1) a word box or a parallel that is an operand of another word (MOVE and BRANCH included, so a word-box feed is bracketed); (2) an enabled comparison used as a value; (3) a nested assignment (y := x := v; is two coils). A call and NOT (…) carry their own brackets. Anything else is a redundant bracket, refused — t1(IN := (a AND b)) included: , and ) already end a pin.

Word or call (P5)

ADD(a)
AND(a, NOT IN2 := b)
x := MUL(, m, 6);

MOVE()
MOVE(a, b) EN c
MOVE(IN := , => x);

A box is its word when every input is a plain positional value, it has at least the word's minimum (2; MOVE 1), its formals are the defaults, its stored type is upper case and its outputs are the default =>. Otherwise it is a call, WORD(…), written like a function — a modified pin, an empty slot, a lowercase type, two MOVE inputs, a named ENO => pin. The call form where the word fits is refused. The NOT box names its pin: NOT(IN := a) is the box; NOT ( + anything else negates that bracket. The named ENO pin and a coil on ENO (MOVE 0 => x EN c / lamp := ENO;) are two stored trees and two texts (0 in the corpora).

Calls — FB instances and functions

An FB call with named input and output pins; an element of an array of FBs heading its call (any variable reference that is no single token is backticked, like an operand); a function with a named output pin, assigned; a function every word does not cover (SEL, LIMIT, MAX, every POU) is a call; a top-level box with no input slot; a box consumed by a main output that is not slot 0, by its stored name (fb(…).name, S4). The FB's type comes from the instance's declaration, so the writer and the reader resolve an instance through the same declarations; `SUPER^` is the base the POU's EXTENDS names (S5). A .name network is shown and kept, never built (MainOutputIndex is read-only on a box a push constructs, N21): a push that changes it is refused.

An unconnected pin is an empty position, never a token. An empty positional slot keeps the call form. An empty coil value takes a negation, x := NOT ;.

NOT and edges

out := NOT a;
out := NOT (a AND b);
up := R_EDGE(clk);
out := F_EDGE(NOT x);
s := R_EDGE(a AND b);
t1(NOT IN := go, PT := pt);

NOT a is the negated contact (a flag); NOT (a AND b) the flag on an AND box's output. Edges are flags, never an R_TRIG box; with a negation the one order is R_EDGE(NOT x) — the vendor negates first (census 1.14, N17), so NOT R_EDGE(x) is refused. TwinCAT's order is unmeasured: its driver refuses R_EDGE(NOT x) on push and shows it as its network's UNSUPPORTED line on pull. A pin's modifier is spelled before its formal.

BRANCH — the drawn parallel (B8, P6)

lamp := start BRANCH (a,
                      b AND (speed LE 40),
                      c);
lamp := start BRANCH (a, b, c) SHORTCIRCUIT;
lamp7 := start BRANCH (a, c BRANCH (b, go));
lamp := BRANCH (a, b);
x := a AND (s BRANCH (b, c));
lamp := start BRANCH (a, , c);

NWL's BoxTreeParallel — what the LD editor draws for a parallel branch, and no OR box. The feed, the word BRANCH, then the branches as a bracketed comma list in stored order. The writer lays the outermost list of a line out one branch per line, aligned under the first; inside brackets that is layout, so one line reads to the same tree. A branch is a slot: a nested parallel needs no brackets, a parallel as a word's operand does. An unfed parallel (5 of 17 in the corpora) has nothing before BRANCH. Mode is derived: the editor creates Sequential, written as nothing; the old short-circuit mode says SHORTCIRCUIT after the list (16 of 17 in the corpora). An empty branch is nothing between its commas (a shorted branch). Refused: one branch (C0023 — it stores, and does not compile), no branch, the empty-terminator feed, and a flag on the parallel.

END_NETWORK

A jump sits where a coil sits — the rung drives it — so it is written as one. JMP l; / RETURN; is the rail (an Assign whose value is the empty terminator, C11), and RETURN := TRUE (a leaf) is not RETURN;. Being a coil, a jump or a return stands beside other coils (the first jump taken wins), takes S=, and nests, y := (JMP l := c);. Labels match case-insensitively; label resolution is the compiler's, so the LSP reports what the build reports:

EXECUTE (P8)

EXECUTE EN bRun
IF bStart THEN
	target := 40 + 2;
END_IF
  END_EXECUTE;
EXECUTE EN go
i := i + 1;
  END_EXECUTE
done := ENO;

A box whose operand is its raw body lines: verbatim, unindented, never read for words. With ; it ends the item; without, it is an open line whose ENO a later line reads (its only output is ENO). The indentation of the END_EXECUTE line and the CR of a CR LF are layout. A snippet holding a line whose first word is END_EXECUTE, or a lone CR, has no spelling.

Backticked operands

t1(IN := a, PT := `DINT_TO_TIME(iRPM)`);
out := a AND `NOT b`;
x := ``;

An operand whose text is not one token stays one operand, verbatim between backticks — never parsed into boxes; `` is the empty-text operand. Operand text that contains a backtick has no spelling.

Members the text does not spell — derived, or dropped (B7)

y := f(a);            // pushed: f's box gets CallType Function, pin name from f's VAR_INPUT, result '   '
y := f(i := a);       // what the next pull shows
x := fb.m(k := a);    // a method's box gets CallType Method

There is no pragma. A member the text does not spell is either derived on push from the text and the declarations, as the editor does, or an editor cache, measured to run the same whatever it holds (DIALECT N40), and dropped when a network is rebuilt. Derived: a FUNCTION's or METHOD's CallType, a FUNCTION's input names (in its declaration's order) and its output list (' ' or ENO, then every VAR_OUTPUT), EN/ENO from the enable. Caches: Fixed, Boolean, the Address sentinel, BranchCounter, operand, instance and pin types, a zero-only pin-flag list, a stored EN/ENO false, the item's jump/return bit, an FB's, program's or conversion's CallType. Lost on rebuild, and named by the push (RebuildLoss): a library function's or an FB's stored output names beyond its text pins, its type spelling. An unchanged network is never rebuilt and keeps every member byte for byte.

The ladder oracle — two rungs

Two rungs as the pull writes them from the vendor's own objects: which item is a Parallel, which box has an ENO output and which slot a pin is on are read off NWL, not inferred. LadderOracleTests pins rungs of these shapes as text and model.

MOVE boxes lighting lamps

NETWORK TITLE: "Machine state"
  split22 := TRUE;
  MOVE 0 => state EN split22 AND (alarm OR warning)
  lampAlarm := ENO;
  split23 := split22 AND NOT alarm AND NOT warning;
  MOVE 1 => state EN split23 AND ready
  lampReady := ENO;
  split24 := split23 AND NOT ready;
  MOVE 2 => state EN split24 AND NOT man AND NOT auto
  lampStandby := ENO;
  MOVE 3 => state EN split24 AND (man OR auto)
  lampRun := ENO;
END_NETWORK

7 items. Each MOVE shows EN/ENO (OutputParams.Names = ['ENO', '']): it writes its result pin, and its lamp reads its ENO on the next line. Both X AND (a OR b) shapes are AND/OR boxes — no Parallel.

An EN/ENO chain into a Parallel

NETWORK TITLE: "Lower the tray"
  split2 := True;
  split3 := split2 AND True;
  split4 := split3 AND pulse;
  edge := rise(CLK := split4);
  edge S= fall(CLK := split4);
  height ADD 5 => height EN split3 AND edge AND (lower OR lowered OR tilt);
  rows MUL rowHeight => t EN split2 AND lower
  t ADD offset => t EN ENO
  lowered S= lower R= ENO BRANCH ((height GE t EN),
                                  down) SHORTCIRCUIT;
END_NETWORK
The last item is the network's one Parallel, fed by the MUL→ADD chain's ENO: the MUL's line is taken by the ADD, the ADD's by the Parallel's feed. The GE has EN shown and unwired and no ENO output, so it is an enabled comparison in a branch — bracketed. The literal True keeps the IDE's spelling.

The shared case set

test/fixtures/network-text/ holds the grammar as cases: accept/*.cases (a text, the NWL model it reads to and, where the writer gives another, its canonical text) and refuse/*.cases (a text and the refusal code with a phrase of its message), each with an optional scope (instance t1 TON, pou f, name x). The bridge's NetworkTextCaseTests and the LSP's network-cases.test.ts read the same files, so "the LSP refuses while typing what a push refuses" is a parity both suites check: a case one side accepts and the other refuses fails both. Every old spelling (P12) is a refuse case whose message names the new one: '+' is not network text: a box is its name — write ADD, `.ENO` is not network text: write the box on its own line without `;`, and read its ENO on a later line with the word ENO, VAR_TEMP is gone, IF … THEN is gone, PARALLEL(…), EN := on a box, {Member := …}, a backticked literal.

The gate

Body language (the IMPLEMENTATION line matches the IDE's view), then parse, then write: a body that reads into a complete model the writer can spell is pushed, in any layout — canonical layout is not a refusal. The written text is the body's canonical form, which the next pull shows. A model the writer cannot spell is refused NETWORK_UNSUPPORTED, at the construct that holds the fact. A separate test oracle (NetworkModelOracle) checks Read(Write(m)) ≅ m over every vendor-read fixture.

Layout after a push. After a successful push the CLI records the IDE's re-materialized — canonical — text as volt/ide and brings the working tree to it, as a formatter would. Only the same program is adopted: an IDE that holds a pushed item as another program is not adopted, so the working tree keeps the pushed text and the next pull brings the IDE's text in as the IDE-side change it is.

The language server

The LSP's network parser (volt-lsp-iec/src/frontend/syntax/network/) is a port of the reader: the same tokens, the same NETWORK_* finding at the same token, so what the editor underlines is what the push refuses — the case set holds the two together. It keeps the statements read before a finding, so hover and the type checks still see them. A split has its own semantic-token class; hovering one shows its definition, VarId and reference count; hovering ENO shows the open line it takes, and BRANCH its branch count and mode. Nothing is reported inside an UNSUPPORTED network. Label diagnostics follow the recorded builds (census 1.15); every token of the text is a format rule, never an LSP-only compiler message.
