Volt ships two front ends over the same core: a **desktop app** and a **VS Code extension**. Same sync, same
language server, same agent — different amounts of setup and control. Both come in the one installer, so this is a
preference, not a purchase.

## The short answer

| | Desktop app | VS Code extension |
| --- | --- | --- |
| Setup | Install and go | A few minutes — VS Code + settings |
| Editor | Volt's own, tuned for PLC work | Full VS Code (and Windsurf) |
| Agent | Built into the window | In the integrated terminal |
| IDE sync | Panel on the right | Volt views in the sidebar |
| Git | Pull / push / build buttons | Your usual Source Control view |
| Extensions | — | Everything you already use |
| Best for | Automation engineers new to git-style tooling | Engineers already living in an editor |

**Not sure?** Start with the desktop app. Nothing is lost if you switch — both drive the same workspace, and you can
run them side by side on the same project.

## The desktop app

One window with everything: the agent on the left, your project's IDE Connection, IDE Sync and Diagnostics on the
right. No editor to configure, no extensions to pick, no terminal required.

**Choose it when**

- You want the fastest path from installer to a synced project.
- Your day is mostly CODESYS or TwinCAT, and the text side is new territory.
- You'd rather click **Pull** / **Push** / **Build** than remember git commands.
- You're evaluating Volt and want to see what it does without setting anything up.

**What you give up** — the editor is deliberately simple. No third-party extensions, no custom keybindings, no
multi-repo workspaces.

## The VS Code extension

The same PLC intelligence inside the editor you already have. Volt adds its own views — IDE Sync, Diagnostics,
Bridge, Agent & Settings — plus Structured Text language support and drift coloring, which shows at a glance which
files the IDE changed versus which ones you changed.

<Figure wide caption="The VS Code extension — Explorer, Source Control and Volt's views side by side, with the agent in the integrated terminal.">
  <VSCode autoplay zoom={0.92} />
</Figure>

**Choose it when**

- You already work in VS Code (or Windsurf) and want PLC code to behave like the rest of your code.
- You want your own extensions, keybindings, themes and tasks.
- You run git from the editor or the terminal and want Volt to stay out of the way.
- Your repo holds more than the PLC project — docs, scripts, CI, a second project.

**What it costs** — a few minutes of setup: install VS Code, let the Volt installer add the extension, open the
project folder, and connect from the Volt view.

## Using both

They share one workspace: the same git repo, the same binding to your live IDE. Pull in one and the other sees it.
A common split is the desktop app on the machine next to the panel, and VS Code at your desk.

The one rule: **don't push from both at the same time**. Push writes to the live IDE, and two writers racing each
other is exactly the mess git is supposed to prevent.
